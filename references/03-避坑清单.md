## 零、六条铁律（比下面 31 条都重要）

### 铁律 1 · 渲染前必须抽 3 帧看，不能只看一帧

**这一条能拦住一半的坑。** 2026-10-20 一天之内，下面四个错全是"没抽帧"造成的：

| 错 | 抽哪一帧能发现 |
|---|---|
| 场景透明度窗口写错，整段空屏 | 那一章中间任意一帧 |
| 浅色线画在浅色底上，完全看不见 | 那一镜任意一帧 |
| 数据图标签在花背景上读不出 | 那一镜"内容最满"的帧 |
| 主标题比切点晚一拍，切点是空的 | 每个 `barF(n)` 那一帧 |

**标准动作**：

```bash
# 抽三类帧：每镜开头（看入场）、每镜中间（看稳定态）、每个切点（看有没有空）
npx remotion still src/index.ts <Id> out/a.png --frame=60
npx remotion still src/index.ts <Id> out/b.png --frame=220
npx remotion still src/index.ts <Id> out/c.png --frame=360
```

然后**逐张看**。不看就等于没检查。

### 铁律 2 · 改工具就要同步改文档

2026-10-20 的实例：`gen_sfx.py` 从 5 个音效扩到 7 个，但 `06-音效设计.md` 还写着"五个基础音效"，
`00` 的索引也写"合成 5 个音效"。文档和工具分头跑，**索引就变成假的**。

**规则**：动 `工具/` 下的脚本，必须同时改引用它的文档；动 `模板/` 下的组件，必须同时改 `00` 的文件结构。

### 铁律 3 · 批量替换代码用行号，不用正则

批量改 `beatF(17)` → `beatF(16)` 时，如果同时有 `beatF(16)` → `beatF(16) - 6`，
**先执行的那条会把新生成的也改掉**（级联污染）。

```python
# ❌ 危险：字符串替换会级联
s = s.replace("beatF(17)", "beatF(16)")
s = s.replace("beatF(16)", "beatF(16) - 6")   # 把上一步的结果也改了

# ✅ 安全：按行号精确替换
lines[612] = re.sub(r"start=\{beatF\([^}]*\)[^}]*\}", "start={beatF(16)}", lines[612])
```

如果非要用字符串替换，**按数值降序执行**（68→67 先做，16→15 后做）。

### 铁律 4 · 交付前必须跑 `check_video.py`，不靠肉眼

这条是 2026-10-21 复盘加的。原因很难看：**本清单第 5 条「切点处画面是空的」写得清清楚楚，
那一轮还是犯了三次。**

> **清单靠记，记不住；能跑的东西才不会被忘。**

```bash
python3 工具/check_video.py 成片.mp4 --expect-fps 30 --expect-dur 45
```

它会逐帧算亮部占比、帧差、静止帧、黑帧，再查音频峰值和静音，最后给 PASS / FAIL 和**具体时间点**。

**三个必须知道的坑**（都是这个脚本自己踩出来的）：

1. **亮部占比必须用原始分辨率算。** 缩到 320×180 会把 1px 细线平均掉，指标失真。
2. **跨片比较必须同分辨率。** 同一支片 960 宽算出 4.23%，1920 宽算出 4.19%，不是一回事。
   要和参考片比，先把成片降采样到参考片的尺寸再算。
3. **静止不等于卡。** 参考片 17617 帧里有 752 帧完全静止（4.3%），它是**故意停在一张图上讲**。
   真正的错是「静止 + 空」。脚本现在分开统计这两个数。

**判据（2026-10 校准）**

| 指标 | 合格线 | 参考片实测 |
|---|---|---|
| 亮部占比 最小 | ≥ 0.8% | 0.88% |
| 「静止且空」帧 | ≤ 5% | 0（它的静止帧都有内容） |
| 音频峰值 | < 0.97 | 1.000（它在削波，别学） |
| 背景最暗 5% 分位 | ≤ 8 | ~6 |

### 铁律 5 · 静止帧超过 2% 就是 PPT，不是"节奏稳"

**这条是 2026-10-22 花了一整轮换来的。**

深睡自由第一版：验收器给 **PASS**，亮部 6.6%、帧差 0.644，看着全都合格。
但**静止帧 188 个（13.9%）**——等于全片有 6 秒画面完全冻住，一帧都没变。
人眼一看就是 PPT 轮播。

**为什么会产生**：线稿是静态的。镜头停住讲东西的时候，如果画面里只有"已经画好的线"，
每帧的像素完全一致，帧差就是 0。

**解法：墨线抖动。** 两条不同频率的正弦叠加，只抖世界层（`camT` 末尾），不抖屏幕层文字：

```ts
const boilX = Math.sin(f * 0.44) * 0.55 + Math.sin(f * 1.03 + 2.1) * 0.22;
const boilY = Math.cos(f * 0.51 + 1.1) * 0.5 + Math.cos(f * 0.97 + 0.4) * 0.2;
const camT = `... translate(${boilX} ${boilY})`;
```

振幅 ±0.72px、单帧位移上限 0.45px。

**必须是平滑正弦。** 早期版本写成"每 3 帧跳 ±0.35px"，那个跳变会闪。

**效果**：静止帧 188 → 5（0.4%），帧差 0.644 → 0.869。

| 版本 | 静止帧 | 帧差均值 |
|---|---|---|
| 补抖动前 | 188（13.9%） | 0.644 |
| 补抖动后 | 5（0.4%） | 0.869 |

**判据**：静止帧 ≤ 2% 合格，5% 以上打回。

> 参考片 17617 帧里有 752 帧静止（4.3%），它是**故意停在一张图上讲**，那些帧是有内容的。
> 线稿风格不一样：停留段的画面本来就只有线，再静止就是纯冻屏，
> 不存在"有内容的静止"这回事。所以这条 2% 只对线稿 / 纸感风格生效。

### 铁律 6 · 验收器 PASS ≠ 可以交付

铁律 4 说"必须跑脚本"，铁律 6 说"**光跑脚本不够**"。

`check_video.py` 只量四件事：亮部、帧差、静止、黑帧。它**量不出**：

- 小人站在床上
- 被子滑到床外
- 手机在搁板淡出后飘在半空
- 表头压住第一行
- 标注糊在人物身体上
- 上一段的面板残影压在新段上

这些全都 PASS 过。

**所以闸门是两道：**

1. `check_video.py` → 数字过关
2. **从成片抽 4～6 帧，逐张看** → 眼睛过关

第二道不能省。省了就会把"小人站在床上"这种片子发出去。

**而且第二道要做多轮，不是一轮。** 2026-10-23 那条片子抽了三轮：
第一轮修字号，第二轮抓出四个构图硬伤，第三轮抓出白纱透字。
每一轮都是**改完之后重新抽**才看得见——改字号会移动所有文字的边界，
改布局会移动所有元素的相对位置，上一次抽的帧全部作废。

> 判定标准：**只要动了 `fontSize` / `x` / `y` / 渲染顺序，就得重新抽一轮。**

```bash
ffmpeg -y -i out/full45.mp4 -ss 17.0 -frames:v 1 out/v_17.png -loglevel error
```

> Remotion 自带一份 ffmpeg，不想装系统版可以走
> `node_modules/@remotion/compositor-darwin-arm64/ffmpeg`（Intel 是 `darwin-x64`）。
> **别用 shell 变量存路径**（`FF=...; $FF`），某些沙箱会拦，直接写全路径。

> 注意：`ffmpeg -vf "select=eq(n\,N)"` 在这个构建里会报解析错误，用 `-ss <秒>` 代替。

## 一、渲染相关

### 1. 渲染静默失败：退出码 1，没有任何报错（仅 Windows 遇到过）

**症状**：`npx remotion render` 跑了几秒就退出，终端什么都没打印，也没生成文件。

**原因**：Remotion 内置的 headless chrome 没下载完整。
去 `node_modules/.remotion/chrome-headless-shell/` 看，只有一个几十 MB 的 zip 和 `download.lock`，
zip 是坏的（正常应该有 150MB+ 且能解压）。

**解决**：直接用本机 Chrome，绕过下载。

```bash
npx remotion render src/index.ts VibeKnowledge out/final.mp4 \
  --browser-executable="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --concurrency=4
```

Mac 上真遇到了同样问题，先把 `node_modules/.remotion` 删掉重装一次，
比指路 Chrome 干净。Edge 也行：`/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge`

---

### 2. 每次渲染出来不一样，粒子位置乱跳

**症状**：预览和成片对不上，浮尘粒子位置每次都变。

**原因**：Remotion 是逐帧渲染的，`Math.random()` 在每一帧都返回不同值。

**解决**：用确定性伪随机——同样的输入永远得到同样的输出。

```tsx
const seeded = (i: number) => {
  const x = Math.sin(i * 127.1 + 311.7) * 43758.5453;
  return x - Math.floor(x);
};

// 用索引当种子，不要用 Math.random()
Array.from({ length: 36 }, (_, i) => ({
  x: seeded(i * 3 + 1) * 1920,
  y: seeded(i * 3 + 2) * 1080,
}));
```

---

### 3. 出片看着发灰、对比度低

**症状**：从成片抽帧看，画面比 Remotion Studio 里看到的淡。

**先别急着改代码**。用 ffmpeg 抽一帧 **PNG** 出来量一下平均色值：

```bash
ffmpeg -ss 26.8 -i final.mp4 -frames:v 1 out/check.png
```

如果 PNG 的平均值和 Studio 截图一致，说明**视频没问题**，是 JPEG 压缩或播放器色彩范围的问题。

Remotion 输出的是 `yuvj420p`（全范围），绝大多数播放器和平台（含抖音）会自动正确处理。
如果确实要强制成标准范围，渲染时加：

```bash
--pixel-format yuv420p
```

## 二、动效相关

### 4. 场景切换时闪一下白

**症状**：切场景的那一两帧整个画面发白、发空。

**原因**：旧场景淡出窗口和新场景淡入窗口不重合，中间有帧"两边都半透明"，背景透出来了。

**解决**：两个场景共用同一段窗口，透明度互补（详见 `02-BGM卡点方法.md` 第五节）。

```tsx
const inP  = interpolate(frame, [from - 9, from], [0, 1], { clamp });
const outP = interpolate(frame, [to - 9, to],     [0, 1], { clamp });
const op   = inP * (1 - outP);
```

---

### 5. 切点处画面是空的

**症状**：场景切过去了，但文字/图形要等半秒才出来，中间一片空白。

**原因**：元素在拍点**才开始**动（`[start, start + dur]`）。

**解决**：元素提前起跑，**在拍点落定**（`[start - dur, start]`）。

这条是卡点视频的核心，改完观感差别非常大。

---

### 6. 节拍越到后面越飘

**症状**：开头卡得准，30 秒处差了两三帧。

**原因**：把"一拍 16 帧"当成了固定值。实际是 15.95 帧，每拍差 0.05 帧，56 拍就差了 2.8 帧。

**解决**：每一拍单独用 `Math.round()` 取整，不要用累加。

```tsx
// ✅
const beatF = (n) => Math.round((0.08 + n * 0.5317) * 30);
```

## 三、音频相关

### 7. 结尾"咔"一声

**症状**：视频最后一帧有爆音。

**原因**：音乐是硬收的，波形在非零点被切断。

**解决**：最后 8 帧做音量淡出。

```tsx
volume={(f) => interpolate(f, [END - 8, END], [1, 0], {
  extrapolateLeft: "clamp", extrapolateRight: "clamp",
})}
```

---

### 8. 片长和音乐长度对不上

**症状**：视频 30 秒，音乐 33 秒，最后 3 秒静音；或者音乐被硬切。

**原因**：按文件时长定的片长。

**解决**：看**能量包络**找音乐真正的结束点，按那个定片长。
`analyze2.py` 输出的 `-- energy per 0.5s --` 段落就是干这个的。

家居篇的素材 33.09s，但 30.05s 之后全是 0，所以片长定 900 帧（30s）。

---

### 9. Remotion 自带的 ffmpeg 是精简版，很多滤镜没有

**症状**：`No such filter: 'acrossfade'`；或者 `Unable to choose an output format for 'x.m4a'`。

**原因**：Remotion 打包的 ffmpeg（`node_modules/@remotion/compositor-*/ffmpeg`）只带渲染必需的编码器，
没有 `acrossfade`、`amix` 这类滤镜，也不能封装 m4a。要这些能力就 `brew install ffmpeg`，用系统那份。

**解决**：
- 音频拼接、交叉淡化 → 用 numpy 自己算（见 `02-BGM卡点方法.md` 第九节）
- 输出格式 → 用 **wav**，Remotion 直接支持，反而更省事
- 只做格式转换（m4a → wav、抽音轨）时它够用

---

### 10. 音效混没混进去，不能用"减法"验证

**症状**：想确认音效有没有进混音，用 `混音 - k × 原曲` 算残差，结果残差到处都是，看不出音效在哪。

**原因**：mp4 里的音轨经过了 44.1k → 48k（AAC）→ 你导出的采样率 这条链路，
和参考音频的 44.1k → 采样率 是**不同的重采样滤波器**，相位和幅度都有差异。
再叠加单声道下混的 0.707 增益，残差能到信号本身的 20%，把音效完全淹没。

**解决**：临时把 BGM 音量设成 0，只渲染一小段，直接看音效轨。

```bash
# 改 [0, 0.85, 0.85, 0] → [0, 0, 0, 0]，只渲染 111 帧
npx remotion render src/index.ts Double11 out/sfxtest.mp4 --frames=150-260
```

30 秒就能出结果，比反复猜快得多。判据：音效峰值时间点要和 `beatF()` 逐个对上。

---

### 11. BGM 开满 1.0，音效一叠就削波

**症状**：混音峰值超过 1.0，导出后有破音。

**原因**：音乐本身已经接近满刻度，音效再叠上去就溢出。

**解决**：BGM 留 15% 余量。

```tsx
volume={(f) => interpolate(f, [0, 5, END - 12, END], [0, 0.85, 0.85, 0])}
```

出片后验一下峰值：

```bash
ffmpeg -i out/final.mp4 -ac 1 -ar 22050 out/check.wav
```

```python
print(np.abs(d).max())   # 应该 < 0.9
```

---

### 12. 音效加太多，听着像廉价广告

**症状**：每个元素都有"叮"一声，很吵。

**解决**：三条红线 ——
① 全片 20~30 个音效封顶；② 同一时刻只放一个；③ chime 全片不超过 3 次。
检验方法：把音量调到很小，还能听出节奏起伏 → 加得对；只剩"噼里啪啦" → 加多了。

## 四、工程相关

### 13. 字体在不同机器上不一样

**症状**：本地好看的宋体，换台机器变成默认黑体。

**原因**：字体名不在目标机器的字体列表里。

**解决**：写完整字体栈，从特殊到通用。

```tsx
const SERIF = "'Source Han Serif SC','Songti SC','STSong','SimSun',serif";
const SANS  = "'PingFang SC','Microsoft YaHei','Hiragino Sans GB',sans-serif";
```

Windows 一定命中 `SimSun`（宋体）/ `Microsoft YaHei`（雅黑），macOS 命中 `Songti SC` / `PingFang SC`。

---

### 14. `tsc` 报错但不影响渲染

**症状**：`npx tsc --noEmit` 报一堆错，`remotion render` 却能正常出片。

**原因**：Remotion 用 esbuild 打包，**不做类型检查**，类型错误会被忽略。

**处理**：渲染不受影响，但建议还是修掉——类型错误往往是真 bug 的前兆。
另外项目里如果有多余的组件文件（没被 `Root.tsx` 引用），它们的报错也会污染输出，可以先挪走。

---

### 15. 想快速看某一帧，别渲染整片

**解决**：用 `still` 单帧渲染，10 秒出图。

```bash
npx remotion still src/index.ts VibeKnowledge out/check.png --frame=258
```

**调优流程**：改代码 → 抽 3~5 个关键帧（每个场景的拍点）→ 看图 → 再改。
确认没问题了才渲染整片，能省 90% 的时间。

## 五、密度与可读性（2026-10 新增）

### 17. 亮部占比上不去，靠加光没用

**症状**：画面发灰、看着"没东西"，于是加一条亮带或提高发光强度，指标上去了，气质没了。

**原因**：亮部占比这个指标，**加光能骗过它，但骗不过眼睛**。参考片最值钱的是背景那个
`rgb(4,6,9)` 的深黑，一条 400px 宽的亮带会把整片暗部洗成灰。

**解决**：
- 提亮靠**加实体内容**（多一张图、多一组数字、多一条对照），不靠加光
- 判断"深黑还在不在"：算背景最暗 5% 分位，**≤ 8 才算合格**（参考片约 6）
- 如果只能靠加光才达标，说明内容本身不够

### 18. 立体感靠亮度差分层，不靠线条数量

**症状**：给 3D 曲面加投影网格地面，想让它"更立体"，结果 22 条地面线 + 22 条曲面线糊成一团，
前后关系反而读不出来了。

**解决**：
- 主方向线：不透明度 0.18–0.72
- 交叉方向线：0.08–0.22
- **靠这两个区间的差分层**，不是靠把所有线都画出来
- 去掉一个方向的地面网格，立体感反而更强

### 19. 1080p 下正文 ≥ 26px、注释 ≥ 20px

**症状**：14–16px 的注释在电脑上看还行，发到手机上完全糊。

**原因**：1080p 缩到手机屏（约 390pt 宽），14px 实际只有 2.8pt。

**解决**：
```
12→18  13→19  14→20  15→21  16→22  17→23
18→24  19→24  20→25  21→26  22→27  23→28
≥24 不动
```
同时把低透明度文字提亮：`0.3x → 0.5x`，`0.42–0.66 → 0.6–0.8`。

**低于 20px 一律不合格。**

### 20. 改字号必须同步重排版面

**症状**：字号一提，四个地方同时撞车——HUD 撞标题、面板标签撞刻度、装饰线仍然隐形、某屏下半空了。

**原因**：字号一变大，所有原本"刚好不撞"的间距会**同时**失效。

**解决**：改完字号立刻检查四件事
1. 顶部 HUD 区：**y < 132 不要放标题**（HUD 文字占到 y≈104）
2. 并排标签的间距（`gap` 要跟着放大）
3. 装饰线粗细（3px 在 66px 字上等于没有，要 6px）
4. 屏内垂直平衡（字变高后下半容易空）

### 21. 每屏至少三层，否则就是 PPT

**症状**：一屏一个大标题 + 一行小字，看着干净，但像幻灯片。

**原因**：短视频的"信息密度"不是字多，是**同时有几层信息在互相支撑**。

**解决**：每屏凑齐三层
- **主体**：图表 / 表格 / 户型图 / 公式 / 3D 曲面（不是大字）
- **数据**：具体数字、对照、区间
- **注释**：来源、前提、限定条件

只有大字的那一屏，删掉或者并到别的屏去。

### 21a. 数字一律 sans + bold，不能用宋体

**症状**：数字字号明明比正文大，看着却比正文弱；「387.8亿」读起来发虚。

**原因**：宋体（SimSun / 思源宋体）的阿拉伯数字**笔画细、字距宽**。
同样 46px，宋体数字的墨量大概只有 sans 的六成，还带着奇怪的边距。

实测：46px 的宋体「387.8亿」视觉重量 ≈ 36px 的 sans bold。

**解决**：
```tsx
// ❌ 数字跟着标题用宋体
<text fontFamily={SERIF} fontSize={46}>387.8亿</text>

// ✅ 数字单独走 sans + bold
<text fontFamily={SANS} fontWeight={700} fontSize={46}>387.8亿</text>
```

**规则**：**凡是阿拉伯数字，不管在哪一层，一律 `SANS` + `fontWeight={700}`。**
中文标题继续用宋体，两者混排时视觉层级反而更清楚。

### 21b. 「文字不清晰」先量对比度，再改字号

**症状**：用户说"文字不够清晰"，第一反应是加深颜色。

**先别改颜色。** 2026-10-23 实测那条片子的四个关键位置：

| 位置 | WCAG 对比度 |
|---|---|
| 底部字幕 | 7.71 : 1 |
| 卡片年份 | 13.85 : 1 |
| 卡片注释 | 11.92 : 1 |
| 钩子标题 | 13.90 : 1 |

全部远超 7:1（AA 级正文只要 4.5:1）。**颜色根本没问题。**

真正的原因永远是这四条里的一条或几条：

1. **字号小** —— 34px 缩到手机屏只剩 12pt 视觉
2. **alpha 低** —— `rgba(43,38,34,0.48)` 在纸底上等于浅灰
3. **字体不对** —— 宋体数字（见 21a）、笔画细的黑体
4. **码率不够** —— 见 21c

**量对比度的方法**：抽一帧，用 PIL 取文字像素和背景像素的 `L` 值，套 WCAG 公式。
算完再决定改什么，不要凭感觉调色。

### 21c. 默认渲染参数会把暗部糊掉

**症状**：渲染器静帧很清楚，成片里小字发毛、边缘发虚。

**原因**：Remotion 默认输出 `yuvj420p` + 默认 CRF，码率只有 2.8 Mbps 左右。
`yuvj420p` 是 full range，播放器按 limited range 解就会发灰；CRF 偏高则暗部糊成一片。

**解决**：渲染一律带上这三个参数

```bash
npx remotion render src/index.ts <Comp> out/x.mp4 \
  --concurrency=4 --log=error \
  --crf=16 --pixel-format=yuv420p --color-space=bt709
```

实测：2.87 → 3.26 Mbps，`yuvj420p` → `yuv420p`，`color_range=tv`，`color_space=bt709`。

**验收时顺手查一遍**：

```bash
npx remotion ffprobe out/x.mp4 | grep -i "Video:"
# 应该是 h264 (avc1) yuv420p(tv, bt709, progressive)
```

## 六、长镜头相关（2026-10-22 新增）

> 这一节全是「一条镜头走完全片」才会遇到的坑。硬切版没有这些问题。

### 22. 小人最后站在床上

**症状**：收尾那一段，主角跑回床边躺下，结果人是**站在床垫上**的。

**原因**：躺下的落点 `x=600`，而床的范围是 `180–760`。终点直接落进了床里。
侧视图看不出"站"还是"躺"，只看到一个立着的人影立在床面上。

**解决**：分两段走——先跑到**床边外侧**站住（`x=800`），再翻身上床躺到 `x=552`。
动作拆成「跑到床边 → 停 → 坐下 → 躺下」，每段之间留 8～10 帧。

**通用判据**：任何"人物终点"都要先查一遍该坐标上有没有家具。
把所有家具的 x 区间列出来，跟 `GUIDE` 关键帧对一遍。

---

### 23. 被子滑上来，露在床外

**症状**：躺下时被子从下方推上来，中途有一截露在床底座下面，甚至穿到地板下面。

**原因**：被子的位移量是按"盖住人"算的，没按"不能出床"约束。

**解决**：给被子加裁切，把它夹在床面范围内：

```tsx
<clipPath id="quiltClip">
  <rect x="180" y="556" width="620" height="152" />
</clipPath>
```

**通用判据**：任何"在容器内位移"的物体（被子、抽屉、窗帘、推拉门），
都要 `clipPath` 夹在容器里。只算位移、不夹边界，一定会露出来。

---

### 24. 搁板淡出了，上面的东西飘在半空

**症状**：光段结束，墙上的搁板淡出，但它上面那个手机没跟着走，
剩一块发光矩形浮在墙上，看起来像 bug。

**原因**：搁板和手机是两个独立的 `opacity`，只给搁板写了退场。

**解决**：**同一组家具共用一个透明度变量。**

```tsx
const shelfOp = out(f, 484, 10);
// 搁板、手机、绿植全部乘 shelfOp
```

或者反过来想：**墙上的家具不该凭空消失**。搁板是墙的一部分，让它常驻，
只让"临时的信息元素"（手机、数据卡）退场。深睡自由最后选的就是这个方案。

**通用判据**：凡是"承托物 + 被承托物"的组合（桌子+杯子、搁板+手机、架子+书），
退场时要么一起走，要么都不走。

---

### 25. 跑动途中整面墙是空的

**症状**：主角从一个站跑到下一个站，中间那段路上，背景只有一片纸色。

**原因**：所有信息元素都绑在"站位"上，站位之间自然什么都没有。

**解决**：**路上要有"不承载信息"的家具**——墙框、踢脚线、地毯、挂画、窗。
它们不需要讲任何东西，只负责让画面不空。

深睡自由实测：加了墙框 + 地毯 + 一面挂画之后，跑回那段（f1216–1300）明显不空了。

**注意**：这些家具必须**不落地**。落地的东西会被跑过去的人穿模（见第 26 条）。

---

### 26. 地板通道必须空着

**症状**：小人走过去，从书桌中间穿过去；或者从绿植的叶子里穿过去。

**原因**：**侧视图没有纵深。** 画面里"在人物后面"的东西，物理上就是"和人物同一个平面"。

**解决**：把地板那条通道（`y ≈ 700–800`）清空。

| ❌ 不能放 | ✅ 可以放 |
|---|---|
| 落地书桌、茶几、落地灯、落地绿植 | 墙上的搁板、桌上的东西、挂画、吊灯 |

人从桌子**前面**走过是合理的（有纵深），人从桌子**中间**穿过是不合理的（没纵深）。
侧视图表达不了前者，所以只能选后者。

**例外（2026-10-23 验证）：把家具渲染在人物之上，地板通道就不用清空。**

```tsx
<Guide f={f} />   {/* 先画人 */}
<Desk f={f} />    {/* 再画家具：家具压住人的下半身 */}
```

侧视图里"家具挡住腿"读起来就是**人站在家具后面**——这正是有纵深时的正确空间关系。
渲染顺序本身就是一种纵深。

代价与前提：
- 家具会连人的**脚**一起挡住，所以家具不能太矮太碎（矮茶几挡不住腿，反而更怪）
- **家具与信息卡在 y 上不能重叠**，否则家具会把卡片切掉
- 人**站在**家具旁边（不重叠）时不受影响，只有走过时才被挡

> 这一条比挪人省事得多。2026-10-23 那条片子试过挪人：2260 → 2076 撞段 4 标题，
> → 2126 撞段 6 标题，最后 2200 才站对。渲染顺序一行就解决走路穿模。

### 27. 半透明白纱盖不住深色轮廓

**症状**：金句压上来，`veil` 已经 0.87，但人头、红色的数字标注还是从字缝里透出来，
看着像错字。

**原因**：白纱是一层均匀的半透明覆盖，它降低的是**对比度**，不是**存在感**。
深色（`P.ink` 的衣服、`P.clay` 的红字）在 0.87 白纱下依然保留 13% 的墨量，
落在浅色背景上就够看了——而金句正好是深色字，两者叠在一起就分不清谁是谁。

**解决**：**该退的元素单独给 `opacity`，不要指望白纱一层盖全部。**

```tsx
// 主角：淡到 8%，只留轮廓
const guideOp = 1 - smooth(clamp01((f - 1252) / 30)) * 0.92;
<g opacity={guideOp}><Guide f={f} /></g>

// 场景里的高饱和标注同理
const tagOp = 1 - smooth(clamp01((f - 1252) / 30)) * 0.9;
<g opacity={tagOp}>
  <text fill={P.clay} fontSize={34}>72</text>
</g>
```

**排查方法**：把金句帧的 `veil` 临时改成 1.0 渲染一张，
剩下还能看见的东西，就是需要单独淡出的东西。

### 28. 信息卡里的注释必须和主体同语义

**症状**：颈椎负荷折线图里塞了一个熨斗 + 「熨烫要通风」。图讲的是低头角度→公斤数，
熨斗讲的是材质安全。读者会把熨斗读成图的一部分，然后完全看不懂这张图。

**原因**：纸感长镜的卡片是"浮在墙上的信息块"，**卡片内部的一切默认属于同一个语义单元**。
往里面加不相干的东西，不是"信息密度高"，是"信息串味"。

**解决**：
- 一张卡只讲一件事。第二个话题要么另起一卡，要么写进底部字幕
- 卡片留白处优先放**同语义的加强信息**——量级类比、极值标注、参照物

那条片子最后把熨斗换成了「27 kg ≈ 一个 8 岁小孩」：
同一张图、同一个数字、只是给了它一个人能感知的参照。信息密度没降，语义通了。

**判断标准**：把这张卡单独截出来给一个没看过片子的人，他能不能一句话说清它在讲什么。

## 七、分发与封面（2026-10-26 新增）

> 这一章的两条，验收器一个都测不出来，人眼抽帧也看不见——
> 它们是"片子做得对，但发不出去"这一类。

### 29. 画面里藏着违禁词

**症状**：成片发出去被限流。这一轮连着踩了两次，一共四处：

| 位置 | 原文 | 类别 | 字号 |
|---|---|---|---|
| 数据卡注释行 | 小红书曝光 / 条笔记 · 小红书 | 站外平台名 | 21px |
| 段 2 大字 | 叫**康复训练**。 | 医疗健康功效 | 62px |
| 段 2 底部字幕 | 给养老院的老人练手指，**抗认知衰退**。 | 医疗健康功效 | 40px |
| 卡片底部标签 | **康复** | 医疗健康功效 | 22px |

**共同点：全都藏在「小字」或者「看起来是事实陈述」的地方。**

数据卡那两处在 21px 的注释行——审片时眼睛全在 46px 的大数字上，四轮抽帧都没看见。

医疗那三处更阴：1971 年瑞典工程师给养老院老人做手指训练，**这是真实历史**。
但「康复训练」「抗认知衰退」是**功效断言**，无资质账号讲就是违规。
**真实不等于能说。** 这是这一轮最贵的一课。

**解决：不要靠肉眼，跑工具。**

```bash
python3 工具/check_words.py src/片子.tsx
python3 工具/check_words.py 文案.md
```

工具从 `.tsx` 里抽**字符串字面量 + JSX 文本节点**（画面上的每一句字），
从 `.md` 里抽全文，按 10 类词库匹配，输出**行号 + 命中词 + 原文**。

| 等级 | 处理 |
|---|---|
| `!!` CRITICAL | 必须改，没有例外 |
| `!` HIGH | 逐条判断，能换就换 |
| `·` LOW | 价格词、运营话术，知识片一般不适用 |

**三类改法**

1. **站外平台名 → 全网口径。** 单平台 387 亿，全网只会更多，
   写「全网 387 亿」是**低估**，安全。
2. **医疗功效 → 只讲行为，不讲功效。**
   「给养老院的老人练手指，抗认知衰退」→「给养老院的老人用，不是给孩子玩的」。
   反转还在（本来不是玩具），功效没了。
   「叫康复训练」→「叫手指练习」。卡片标签「康复」→「练手」。
3. **表述连带改。** 去掉「一年之内，四个平台数字」里的「平台」之后，
   「口径不同，不可相加」就悬空了，得跟着换成「来源不同，只看量级」。

**误报怎么认**：`offset="100%"`、`width="100%"` 这类 SVG 参数会命中「100%」。
工具已过滤「不含中文且不含 3 个以上连续字母」的字符串，剩下漏的看一眼行号就知道。

**话题标签同理**：用 `#家居`，不用 `#家居好物`。
「好物 / 推荐 / 种草」会把内容推进电商流量池，非带货账号会被判营销。
基准片用的是 `#睡眠质量 #卧室 #家居 #生活常识 #知识科普`——全是内容词。

**项目文档里的命中不用慌**：`数据.md` / `脚本.md` 是内部台账，
里面会记录「小红书 100 亿」「不能碰疗效宣称」这类原文，那是资料不是发布内容。
**只改源文件和要发出去的那份文案。**

**排查顺序**（限流时按这个走，别乱猜）：

| 顺序 | 嫌疑 | 怎么验证 |
|---|---|---|
| 1 | 画面 / 文案里的违禁词 | `check_words.py` 跑一遍，CRITICAL 清零 |
| 2 | 话题标签带货 | 换成内容词重发 |
| 3 | 价格词 / 促销词 | 同一次扫描的 LOW 项 |
| 4 | 内容类目（医疗健康需认证） | 有无「治疗 / 疗效 / 抗某某」 |
| 5 | BGM 版权 | **先看别的片子是不是同一首**——同一首且别的没事，就不是它 |

第 5 条特别值得说：三条片子 BGM 完全相同，其中一条没被限流，
所以 BGM 直接排除。**横向对比比单条分析快得多。**

### 30. 封面在列表里糊成一块色块

**症状**：封面单独看还行，缩到抖音列表那种 200px 宽，主体变成一块红色方块，
观众完全看不出画的是什么。

**原因有两个，都跟"缩小"有关：**

1. **小尺寸像素画没留边。** 7×7 板子画心形，每格 60px，
   红色格子彼此贴着，缩到 200px 就糊成一片。
   **图形是靠周围的空读出来的，不是靠填充本身。**
   改成 9×9 板、图形 7×7 居中，四周留一圈空孔——轮廓立刻出来。
2. **少了辨识特征。** 拼豆画成"圆角方块 + 高光"，看着像糖果、像巧克力。
   拼豆真正的辨识特征是**中心那个孔**。补一个深色小圆孔，一眼就是拼豆。

**通用规矩**：任何主体图形，先问一句「去掉颜色，只看轮廓，还认得出吗」。
认不出就是形不够，不是色不够。

**尺寸与安全区**

| 项 | 值 |
|---|---|
| 尺寸 | 1080×1440（3:4），抖音主页列表就是这个比例 |
| 不能用 | 视频首帧——16:9，在列表里两边被裁 |
| 安全区 | x 60–930 / y 60–1150 |
| 底部 290px | 会被标题和作者名盖住，不放关键信息 |

**验收方法**：把封面缩到 200px 宽看一眼。主体还认得出、标题还读得清，才算过。
这一步十秒钟，能省掉一次"发出去发现封面废了"。

**主体从哪来（2026-10-26 补）**：不要为封面另画一个东西。
**从片子里挑那个招牌镜头**——观众点进去第一眼就能认出的画面。
拼豆片用拼豆板，大字片用斜的仪表板。封面和正片是同一支片，
主体是两回事，点进去会有"被换了片子"的错位感。

**主体优先选暗的**：满屏米白里放一块深色，信息流里最跳。
这也是把正片的暗场风格复用到封面上——一张封面里就给出了「白转黑、平面转三维」。

## 八、风格变换（2026-10-26 新增）

### 31. 风格变换做出了"雾"和"空拍"

**症状**：想从白转到黑，结果中间那段变成一片浑浊的灰褐，像雾不像关灯；
段落交界处黑底上只剩一个小人，像卡住了。

用户 2026-10-26 的方向是「不同的内容可以尝试更大胆的动效、背景、风格变换，
例如从白转到黑，由平面到三维」。做的时候踩了四个坑：

| 坑 | 表现 | 改法 |
|---|---|---|
| **过渡给太长** | 灯灭用了 36 帧，中间 1.2 秒是一片灰 | **20 帧（0.67s）**，快才像关灯 |
| **文字和换光同时进行** | 字糊在灰里，两头都不清楚 | **前段文字先走 → 换光 → 后段文字后到**，中间空 6～14 帧 |
| **段间留空拍** | 上一段退了、下一段没到，黑底上只有一个人 | **交接差 10 帧以内**，验收器会抓「静止且空」 |
| **压白往纸色推** | 亮部占比跌到 0.67%，89 帧「静止且空」，FAIL | **往更亮的暖白推 `#fdf8ec`**，纸色亮度低于「亮部」阈值 |

**四条规矩**

1. **风格变换靠换光，不靠剪辑。** 镜头一条到底，观众却感到换了世界——
   这是「长镜」和「大胆」能同时成立的唯一办法。硬切就破了片型。
2. **暗场分两层画。** 会被压暗的画在暗色遮罩**下面**；要亮着的画在遮罩**上面**，
   用 `mix()` 切到亮版。遮罩 **0.98**，留 2% 保住纸纹——全黑会被判「黑帧」。
3. **三维不用 CSS 3D。** SVG `<g>` 上不可靠。用「顶面四边形 + 前唇」的实体板，
   和家具同一套透视；圆盘改椭圆 `ry = 0.84 rx`，刻度按 `sin/cos` 投影。
   **数字和标签保持直立**——斜文字毁掉 22px 的可读性。
4. **抖动开关也是语义。** 抖动 = 人手，不抖 = 机器。跟着内容开关，
   不要全片一个手感。

**验收数字会变**：有暗场的片子亮部占比明显升高（17.53% vs 8.78%），这是正常的。
帧差反而可能略低（收尾压白没有大动作）。跨片比较要看同一支片的前后版本，
不要拿有暗场的片子和全程暖白的片子直接比。
