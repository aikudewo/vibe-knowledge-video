# 音效设计

> 画面卡点是"看得准"，音效卡点是"听得见"。
> 没有音效的卡点视频，节奏是软的。

---

## 一、先想清楚：音效是标点，不是台词

音效在片子里的作用只有三个：

| 作用 | 用在哪 | 声音 |
|---|---|---|
| **标点** | 元素落定、行末 | 短、脆、快 |
| **转场** | 场景切换 | 有方向感、有长度 |
| **强调** | 数据、金句 | 有音高、有余韵 |

**判断标准**：把所有音效去掉，片子还成立吗？成立 → 音效加得对（是加分项）。
如果去掉就不成立了，说明画面本身没卡住点，音效在替画面干活。

## 二、七个基础音效（够用 95% 的片子）

不用去找音效库。**用 numpy 合成**，可控、无版权风险、体积小（七个加起来不到 300KB）。

### 2.1 合成脚本

```python
import wave
import numpy as np

SR = 44100

def save(name, sig, peak=0.9):
    sig = np.asarray(sig, dtype=np.float32)
    m = np.abs(sig).max()
    if m > 0:
        sig = sig / m * peak
    # 首尾 5ms 淡入淡出，避免爆音
    n = int(0.005 * SR)
    sig[:n] *= np.linspace(0, 1, n)
    sig[-n:] *= np.linspace(1, 0, n)
    w = wave.open(name, "wb")
    w.setnchannels(1); w.setsampwidth(2); w.setframerate(SR)
    w.writeframes((np.clip(sig, -1, 1) * 32767).astype(np.int16).tobytes())
    w.close()

t = lambda d: np.arange(int(d * SR)) / SR
```

### 2.2 pop —— 元素落定（最常用）

音高快速下滑 + 极短衰减。这是 UI 音效的通用形状。

```python
t_ = t(0.13)
f = 980 * np.exp(-t_ * 22) + 260            # 音高从 980 滑到 260
phase = 2 * np.pi * np.cumsum(f) / SR
pop = np.sin(phase) * np.exp(-t_ * 42)       # 42 = 衰减速度
pop += np.random.randn(len(t_)) * np.exp(-t_ * 320) * 0.35   # 起始瞬态
save("pop.wav", pop, 0.8)
```

**调参**：想要更"木"就降低起始频率；想要更"脆"就加大噪声瞬态。

### 2.3 whoosh —— 场景转场

噪声 + 时间变化的低通滤波（低通截止频率先升后降 = 空气被"扫过"的感觉）。

```python
t_ = t(0.6)
noise = np.random.randn(len(t_))
sweep = np.exp(-((t_ - 0.3) ** 2) / (2 * 0.11**2))   # 中段最强
a = 0.012 + 0.5 * sweep                                # 低通系数
y = np.zeros_like(noise)
prev = 0.0
for i in range(len(noise)):
    prev = prev + a[i] * (noise[i] - prev)             # 一阶低通
    y[i] = prev
save("whoosh.wav", y * sweep, 0.55)
```

**注意**：这个 for 循环在 0.6 秒上跑 26000 次，Python 里也就几十毫秒，不用向量化。

### 2.4 chime —— 数据 / 金句

三个泛音叠在一起，各自不同衰减速度，就有了"钟"的质感。

```python
t_ = t(1.1)
chime = np.zeros_like(t_)
for freq, amp, dec in [(1046.5, 1.0, 4.5), (1568.0, 0.55, 6.0), (2093.0, 0.3, 8.0)]:
    chime += amp * np.sin(2 * np.pi * freq * t_) * np.exp(-t_ * dec)
save("chime.wav", chime, 0.6)
```

`1046.5 / 1568 / 2093` 是一个大三和弦（C6），听起来"上扬"。想更中性就用纯五度。

### 2.5 tick —— 清单逐行

噪声做一阶差分（简易高通），极短衰减。

```python
t_ = t(0.05)
n = np.random.randn(len(t_))
n = np.diff(np.concatenate([[0], n]))
save("tick.wav", n * np.exp(-t_ * 150), 0.5)
```

### 2.6 thud —— 低频强调

```python
t_ = t(0.35)
f = 95 * np.exp(-t_ * 6) + 48
phase = 2 * np.pi * np.cumsum(f) / SR
save("thud.wav", np.sin(phase) * np.exp(-t_ * 11), 0.75)
```

### 2.7 paper —— 撕纸（纸片 / 拼贴场景）

噪声 + 随机尖峰（模拟纤维断裂）+ 高通（去掉闷的低频）。

```python
t_ = t(0.55)
noise = np.random.randn(len(t_))
env = np.exp(-t_ * 6.5) * (1 - np.exp(-t_ * 140))     # 起音快、尾音短
spikes = (np.random.rand(len(t_)) > 0.996) * np.random.randn(len(t_)) * 2.4
sig = (noise * 0.55 + spikes) * env
sig = np.diff(np.concatenate([[0], sig]))             # 简易高通
save("paper.wav", sig, 0.65)
```

**关键**：`spikes` 那一行不能省。纯噪声是"沙沙声"，加上稀疏尖峰才是"撕"的质感。

### 2.8 stamp —— 盖章（落款 / 收尾）

低频砸击 + 纸面拍击。音高从 150Hz 快速落到 52Hz。

```python
t_ = t(0.5)
f = 150 * np.exp(-t_ * 9) + 52
phase = 2 * np.pi * np.cumsum(f) / SR
sig = np.sin(phase) * np.exp(-t_ * 13)
sig += np.random.randn(len(t_)) * np.exp(-t_ * 95) * 0.45   # 纸面拍击
save("stamp.wav", sig, 0.85)
```

**关键**：第二个加号里的噪声衰减要极快（`95`），否则会变成"沙锤"而不是"拍下去"。

## 三、挂载：用 Sequence 踩拍

**不要**把音效预混进 BGM。用 `Sequence` 挂，这样画面改了音效自动跟着走。

```tsx
const SFX: React.FC<{ at: number; name: string; vol?: number }> = ({
  at, name, vol = 0.6,
}) => (
  <Sequence from={Math.max(0, at)} durationInFrames={40}>
    <Audio src={staticFile(`sfx/${name}.wav`)} volume={vol} />
  </Sequence>
);
```

### 分配规则

| 事件 | 音效 | 起跑点 | 说明 |
|---|---|---|---|
| 场景切换 | whoosh | `场景起点 - 12 帧` | 噪声峰值正好落在切点，不是切点才开始 |
| 卡片/文字落定 | pop | 落定的那一拍 | 和画面同一个 `beatF()` |
| 清单逐行 | tick | 每行的拍点 | 音量比 pop 小一点 |
| 数据 / 金句 | chime | 强调的拍点 | 有余韵，别密集使用 |
| 大字落定 | thud | 拍点 | 低频，一两条就够 |

```tsx
const SoundDesign: React.FC = () => {
  const cues: { at: number; name: string; vol: number }[] = [];

  // 转场
  [S2, S3, S4, S5, S6, S7, S8].forEach((s) =>
    cues.push({ at: s - 12, name: "whoosh", vol: 0.50 })
  );
  // 卡片逐张
  for (let i = 0; i < 5; i++)
    cues.push({ at: beatF(10 + i), name: "pop", vol: 0.70 });
  // 清单逐行
  for (let i = 0; i < 5; i++)
    cues.push({ at: beatF(62 + i), name: "tick", vol: 0.62 });

  return <>{cues.map((c, i) => <SFX key={i} {...c} />)}</>;
};
```

## 四、音量标定（最容易被忽略的一步）

### 4.1 先定 BGM，再定音效

BGM 留 15% 余量，别开到 1.0：

```tsx
volume={(f) => interpolate(f, [0, 5, END - 12, END], [0, 0.85, 0.85, 0])}
```

这样音效叠上去不会削波。混音峰值控制在 **0.85 以内**。

### 4.2 音效电平：目标 -13dB 左右

实测数据（BGM 0.85 时）：

| vol 参数 | 实测峰值 | 听感 |
|---|---|---|
| 0.30 | 0.09 | 几乎听不见 |
| 0.46 | 0.14 | 太轻，被音乐盖住 |
| **0.70** | **0.21（-13dB）** | **刚好，能感觉到但不抢** |
| 0.90 | 0.27 | 开始像廉价广告 |

**经验值**：

```
pop    0.70
tick   0.62
thud   0.60
chime  0.55
whoosh 0.50
```

> 注意 `vol` 和实际峰值不是 1:1 的（0.46 的 vol 只出 0.139 的峰），
> 因为 pop 是极短瞬态，5ms 淡入吃掉了起音。**按实测标定，不要按理论算。**

## 五、验证：把 BGM 静音，单独渲染一段

**错误做法**：用"混音 - k × 原曲"做减法。
因为 AAC 编码 + 重采样会引入大量残差，测出来全是噪声，什么也看不出来。

**正确做法**：临时把 BGM 音量设成 0，渲染一小段，直接看音效轨。

```bash
# 1. 临时改代码
#    [0, 0.85, 0.85, 0] → [0, 0, 0, 0]

# 2. 只渲染 111 帧（约 3.7 秒），30 秒出结果
npx remotion render src/index.ts Double11 out/sfxtest.mp4 --frames=150-260

# 3. 抽音轨，看能量峰
ffmpeg -i out/sfxtest.mp4 -ac 1 -ar 22050 out/sfx.wav
```

```python
import wave, numpy as np
w = wave.open("out/sfx.wav", "rb"); sr = w.getframerate()
d = np.frombuffer(w.readframes(w.getnframes()), dtype=np.int16).astype(np.float32) / 32768.
step = int(0.05 * sr)
for i in range(len(d) // step):
    v = float(np.sqrt((d[i*step:(i+1)*step] ** 2).mean()))
    if v > 0.005:
        print("%5.2fs %.3f" % (i * 0.05, v))
```

**判定**：输出的时间点要和你预期的拍点**逐个对上**。

实测例（渲染帧 150-260）：

```
0.30s  ← beatF(10) = 159 帧
0.80s  ← beatF(11) = 175 帧
1.35s  ← beatF(12) = 191 帧
1.90s  ← beatF(13) = 207 帧
2.40s  ← beatF(14) = 223 帧
3.20s  ← 场景转场 whoosh
```

对上了就是对的。对不上，检查 `Sequence from` 是不是用了帧号而不是秒。

## 六、别过度

三条红线：

1. **不是每个元素都要有音效**。一张片子 20~30 个音效封顶，超过就是噪音。
2. **同一时刻只放一个音效**。两个音效撞在一起，会互相抵消成"噗"的一声。
3. **音效不重复旋律**。chime 用多了会变成"叮叮叮"的廉价感，全片 2~3 次足够。

> 检验方法：把音量调到很小，还能听出节奏的起伏 → 音效设计是成功的。
> 调到很小只剩"噼里啪啦" → 加太多了。
