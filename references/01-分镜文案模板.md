# 分镜与文案模板

> 短视频的胜负 80% 在文案。画面只是让文案"踩上点"。
>
> **先看 `05-选题研究与爆款文案.md`**：那篇讲"怎么想出这些句子"（检索、热点、风格卡、8 种钩子）。
> 这篇讲"句子想好了，怎么摆成 5 个场景"。

---

## 一、五场景结构

### 场景 1 · 钩子（2 小节 / 约 4.3 秒）

**作用**：3 秒内让人决定要不要继续看。不解释、不铺垫，直接把主张扔出来。

**版式**：居中大字，两行，第二行用强调色。

**句式**：
- `X，应该花在 / 对自己好的地方`
- `你以为的 A，其实 / 是 B`
- `90% 的人，都 / 搞反了`
- `别急着买 X，先看 / 这一条`

**注意**：主标题不超过 12 个字，超了就要换行，字号会掉。

> 别用第一反应想到的那句。**从 8 种钩子模型里筛一遍再定**，筛选标准和完整模型表见 `05-选题研究与爆款文案.md` 第五节。

---

### 场景 2 · 反常识（2 小节 / 约 4.3 秒）

**作用**：制造认知冲突，让人产生"啊？"的反应。**必须带数字**。

**版式**：一句标题 + 左右两张对比卡（左差右好），中间一个 `vs`。

**句式**：
- `最贵的消费，往往发生在别人看不见的地方`
- `A 花 8000，一次 400；B 花 4000，一小时 1.4`
- `你买的不是 X，是 Y`

**数字的用法**：把总价换算成**单次成本**或**每小时成本**，冲击力立刻翻倍。
- 8000 的大衣 ÷ 20 次 = 400 元/次
- 4000 的床垫 ÷ (8h × 365) = 1.4 元/小时

---

### 场景 3 · 清单（4 小节 / 一项一小节）

**作用**：干货主体。**这是全片唯一的"信息量"段落**，也是收藏率的来源。

**版式**：左侧 4 行清单（逐条点亮），右侧同步显示当前项的图标、大数字、标题、补充句。

**每项的内容配比**：
| 元素 | 要求 | 例 |
|---|---|---|
| 名称 | 3~5 字，具体物件 | 一把椅子 |
| 数字 | 一个可量化的时长/金额 | 8 小时/天 |
| 标题 | 一句判断，带态度 | 先买一把坐得住的椅子 |
| 补充句 | 一句人话解释，15~25 字 | 腰椎的账，十年后会一起结清 |

**节奏**：一项占一小节（64 帧）。第 1 拍：图标+数字+标题一起落；第 3 拍：补充句落。

**四件的选择原则**：覆盖一天的主要场景（坐 / 看 / 睡 / 吃），不要选同类。

---

### 场景 4 · 算总账（2 小节）

**作用**：把前面零散的清单**合并成一个结论**，制造"原来如此"的爽感。

**版式**：一条 24 小时分段色条，四段依次生长，每段踩一拍。

**句式**：
- `这些加起来，就是你的一整天`
- `8h 坐着 + 3h 有光 + 8h 睡着 + 5h 吃着 = 24h`
- `这不叫消费，是把 24 小时重新分配一遍`

**关键**：各段数字**加起来要等于总数**。这里 8+3+8+5=24，正好一天，视觉和逻辑同时闭环。

---

### 场景 5 · 收尾（4 小节 / 约 8.5 秒）

**作用**：金句截图位 + 落款。抖音的"收藏"和"转发"大多发生在这 8 秒。

**版式**：
1. 第 1 句金句（主色）
2. 第 2 句金句（强调色）—— 两句构成对仗
3. 四张单品卡逐拍弹出
4. 细线 + 落款

**句式**（对仗最关键）：
- `钱花在看不见的地方 / 生活会在看得见的地方还给你`
- `对自己好一点 / 不是奢侈，是本分`
- `先照顾好看不见的地方 / 看得见的生活自然会好`

---

## 二、抖音文案的六条语感规则

1. **短句**。一句话不超过 15 字，能断就断。屏幕上每行字都要能一口气读完。
2. **数字前置**。能用数字就不用形容词。"8000 的大衣"比"很贵的大衣"有力十倍。
3. **具体名词**。写"床垫"不写"睡眠用品"，写"那口锅"不写"厨房用具"。
4. **反差结构**。"别人看得见 / 看不见"、"8000 一次 400 / 4000 一小时 1.4"。
5. **说人话**。不写"提升居住体验"，写"腰椎的账，十年后会一起结清"。
6. **留一个钩子**。结尾用问句引导评论，别用"点赞关注"这种硬广。

## 五、进阶结构：8 场景 / 21 小节（45 秒）· v1 硬切版

> **这一节是硬切版的做法。** 2026-10-22 之后的新片默认走第六节「长镜版」。
> 硬切版的场景切点就是 PPT 换页感的来源，只有在题目本身没有空间叙事时才退回这一套。

当选题需要"细讲"时，5 场景塞不下。用 8 场景，多出 3 小节专门讲两样东西。

| # | 场景 | 小节 | 作用 | 关键做法 |
|---|---|---|---|---|
| 1 | 钩子 | 2 | 主张 + **时效信息** | 比 5 场景版多一行小字（日期/开售时间） |
| 2 | 总览 | 2 | 卡片墙一次铺开 | 5 张 3D 卡逐拍弹出，先给全貌 |
| 3 | 细讲 ① | 3 | 数据 + 3 个判断点 + 价格带 | 第 1 小节给数据，后 2 小节给"看什么不看什么" |
| 4 | 细讲 ② | 3 | 同上，换另一类 | 结构完全对称，观众第二次就熟悉了 |
| 5 | 快讲 ③④⑤ | 3 | 一类一小节，一句话讲完 | 卡片式，节奏明显加快 |
| 6 | 避坑 | 2 | 反着看，制造反差 | **最有转发欲的一段** |
| 7 | 清单表 | 3 | 五行表格逐行点亮 | 收藏动机最强的画面 |
| 8 | 收尾 | 3 | 金句 + 图标 + 落款 | 图标行回顾全片 |

### 为什么要有"避坑"这一段

正面推荐是"我在告诉你买什么"，避坑是"我在告诉你别被坑"。
后者的信任度高得多——**观众会因为你劝他别买而相信你劝他买**。

写法：用数据支撑，不要凭感觉。

- 双11 案例：「灯具、沙发桌椅、空气净化器都是非当季回落品类，双 11 也不会便宜」
- 依据来自行业数据：灯具、空调这类淡季品类在双11 期间 GMV 持续回落

## 六、长镜版：8 站 / 21 小节（45 秒）· 当前标准

> 一条镜头走完，0 次硬切。分镜不是"切几个场景"，而是**"主角在哪几站停下来"**。
> 案例：《深睡自由》纸感长镜版，源文件 `模板/Paper45.tsx`。

### 6.1 长镜分镜要出四张表

硬切版只要一张「场景表」。长镜版要四张，因为要同时管住镜头、人物、信息和层级。

| 表 | 管什么 | 写在哪 |
|---|---|---|
| **① 站位表** | 镜头在哪停、停多久、推到多少 | 代码里的 `CAM` |
| **② 动作表** | 主角走到哪、什么时候停、什么时候躺下 | 代码里的 `GUIDE` |
| **③ 分镜表** | 每一站讲什么、画面主体是什么 | `项目/片名/分镜表.md` |
| **④ 层级表** | 哪些东西跟着镜头走、哪些钉在屏幕上 | 写组件时对照 |

**四张表必须互相对齐**：站位表的停住区间，就是动作表里主角站住的区间，
也就是分镜表里"出信息"的区间。三个对不上，就会出现"人还在走，字已经出来了"。

### 6.2 ① 站位表（CAM）

只写 4 个字段：帧号 `f`、镜头中心 `cx/cy`、缩放 `k`。

**规则：`k` 必须单调递增**（1.02 → 1.10）。这样即使 `cx/cy` 不变，画面也一直在缓慢推进，
不会出现"完全静止"的帧。

```ts
const CAM = [
  { f: 0,    cx: 640,  cy: 545, k: 1.02 },   // 起点
  { f: 128,  cx: 640,  cy: 545, k: 1.03 },   // 第 1 站 · 停（讲完钩子）
  { f: 170,  cx: 950,  cy: 545, k: 1.03 },   // 走向第 2 站
  { f: 288,  cx: 950,  cy: 545, k: 1.04 },   // 第 2 站 · 停
  { f: 330,  cx: 1250, cy: 550, k: 1.045 },
  { f: 500,  cx: 1250, cy: 550, k: 1.055 },  // 第 3 站 · 光
  { f: 520,  cx: 1950, cy: 555, k: 1.06 },
  { f: 676,  cx: 1950, cy: 555, k: 1.065 },  // 第 4 站 · 声
  { f: 716,  cx: 2750, cy: 555, k: 1.07 },
  { f: 860,  cx: 2750, cy: 555, k: 1.075 },  // 第 5 站 · 温
  { f: 904,  cx: 3350, cy: 560, k: 1.08 },
  { f: 1056, cx: 3350, cy: 560, k: 1.085 },  // 第 6 站 · 压
  { f: 1216, cx: 700,  cy: 545, k: 1.09 },   // 跑回床边
  { f: 1300, cx: 620,  cy: 545, k: 1.10 },
  { f: 1350, cx: 600,  cy: 545, k: 1.10 },   // 躺下 · 收尾
];
```

**走与停的比例**：走 30～50 帧，停 150～210 帧。
走的时间太长会拖，太短会像瞬移。

### 6.3 ② 动作表（GUIDE）

字段：`x`（横坐标）、`hip`（髋部高度）、`tRot / lRot`（躯干/腿的旋转）、
`aR / aL`（手臂角度）、`walk`（走路强度 0～1）。

```ts
const GUIDE = [
  { f: 0,    x: 820,  hip: 470, tRot: 0, lRot: 0, aR: 10, aL: -8, walk: 0 },
  { f: 128,  x: 820,  hip: 470, tRot: 0, lRot: 0, aR: 12, aL: -6, walk: 0 },   // 站住讲
  { f: 170,  x: 1000, hip: 470, tRot: 0, lRot: 0, aR: 10, aL: -8, walk: 1 },   // 走到第 2 站
  { f: 288,  x: 1000, hip: 470, tRot: 0, lRot: 0, aR: 12, aL: -6, walk: 0 },
  // … 依次到 x = 1150 / 1850 / 2560 / 3080
  { f: 1216, x: 900,  hip: 470, tRot: 0, lRot: 0, aR: 10, aL: -8, walk: 1 },   // 跑回
  { f: 1300, x: 600,  hip: 470, tRot: 0, lRot: 0, aR: 10, aL: -8, walk: 0 },
  { f: 1322, x: 552,  hip: 430, tRot: -78, lRot: 78, aR: 20, aL: -20, walk: 0 }, // 躺下
];
```

**走路的两个小动作**（不加就僵）：

```ts
const sw  = walk * Math.sin(f * 0.62) * 17;   // 肩膀左右摆
const bob = walk * -5;                        // 走路时整体下沉
```

**躺下时要让腿淡出**，否则腿会扫过床垫：

```ts
const legOp = Math.max(0,
  1 - smooth(clamp01((f - 300) / 2)) + smooth(clamp01((f - 310) / 3)));
```

### 6.5 ④ 层级表

| 世界层（在 `camT` 里，跟着镜头走） | 屏幕层（在 `camT` 外，钉在画面上） |
|---|---|
| 小人 | 段标题 |
| 床 / 窗 / 搁板 / 地毯 / 挂画 | 脚注 / 来源 |
| 图表卡、数据卡、剖面图 | 清单表、金句 |

### 6.7 排的时候先自查三条

1. **站位帧是不是落在小节线上？** `f ÷ 63.83` 应该接近整数。
2. **主角有没有一段长时间站着不动、画面也没信息变化？** 有 → 加信息或缩短停留。
3. **每段是不是三层齐全？** 只有大字的那一段，删掉或者并到隔壁。
