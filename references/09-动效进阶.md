# 动效进阶

> 动效不好看，90% 不是"手法不够花"，是**缓动不对**和**落点不准**。  
> 先把这两件事做对，再谈手法。

---

## 一、先诊断：现在的动效差在哪

之前两条片子的动效只有三样：淡入上移、spring 弹入、3D 卡片翻转。问题不在"少"，在三个细节：

| 症状          | 原因                          | 解法                                 |
| ----------- | --------------------------- | ---------------------------------- |
| 看着"平"，没有质感  | 全程只用 `translateY + opacity` | 换成**遮罩擦除**，有"被揭开"的物理感              |
| 快速移动时发虚、闪烁  | 单帧位移超过 20px，眼睛跟不上           | 加**运动模糊**（Trail）                   |
| 转场像 PPT     | 只有交叉淡化                      | 用 `pushCut` / `iris` / `blurSlide` |
| 元素同时出现，没有层次 | 所有元素同一帧起跑                   | **逐字/逐项级联**（stagger）               |
| 弹入"飘"，不像有重量 | `damping` 太大，没有回弹           | 降到 9~12，配合 `mass`                  |
| 落地没有反馈      | 没有挤压变形                      | **squash & stretch**               |

## 二、spring 的正确用法（最容易被浪费的 API）

大多数人只用了 `spring({frame, fps, config})`，其实它还有四个参数能救很多场景。

```tsx
const s = spring({
  frame: frame - start,     // 起点
  fps,
  config: {
    damping: 12,            // 阻尼：越小越弹，越大越稳
    mass: 0.6,              // 质量：越小越快
    stiffness: 120,         // 刚度：越大越硬
  },
  durationInFrames: 16,     // ★ 把曲线拉伸到正好 16 帧结束
  delay: 0,                 // ★ 延迟多少帧开始
  overshootClamping: false, // ★ true = 不允许冲过目标值
  reverse: false,
});
```

### 2.1 `durationInFrames`：让弹簧"正好落在拍上"

**这是卡点视频最有用的一个参数。**

默认的 spring 时长由物理参数决定（可能 18 帧，也可能 23 帧），你没法精确控制它什么时候停。  
加上 `durationInFrames: 16`，它就**正好在 16 帧后到位**——正好是一拍。

```tsx
// 一拍 = 16 帧，弹簧正好在一拍内完成
const p = spring({ frame, fps, config: { damping: 12 }, durationInFrames: 16 });
```

### 2.2 三组调好的预设（直接抄）

| 用途            | config                                       | 观感        |
| ------------- | -------------------------------------------- | --------- |
| **卡片弹出**（有回弹） | `{ damping: 11, mass: 0.5, stiffness: 140 }` | 弹一下，像被扔上去 |
| **文字落定**（干脆）  | `{ damping: 200 }`                           | 不弹，直接停，最稳 |
| **重物落地**（很弹）  | `{ damping: 9, mass: 0.9, stiffness: 90 }`   | 明显过冲，有重量  |

> `damping: 200` 是 Remotion 社区常用的"无回弹"写法，  
> 因为 damping 远大于临界阻尼时，曲线就是标准的缓出。

### 2.3 `measureSpring()`：想知道弹簧到底多长

```tsx
import { measureSpring } from "remotion";
const len = measureSpring({ fps, config: { damping: 12 } }); // 比如 23
```

## 三、八种手法（配套 `模板/MotionLab.tsx`）

实验室组件里有八个格子，每个独立循环 2 秒，可以直接对照看。

### 3.1 遮罩擦除（最值得换掉淡入）

淡入是"透明度从 0 到 1"，擦除是"内容被一条线揭开"。后者有方向、有速度感。

```tsx
const p = interpolate(t, [0, 16], [0, 1], { easing: Easing.out(Easing.cubic) });

<div style={{ clipPath: `inset(0 ${(1 - p) * 100}% 0 0)` }}>文字</div>
// 可选：加一条跟随的竖线，视觉上像"笔尖"
```

**变体**：`inset(0 0 ${(1-p)*100}% 0)` 从下往上揭；`circle(${r}px at 50% 50%)` 是光圈。

### 3.2 弹簧过冲

见第二节。关键是把 `damping` 压到 9~12，让它**冲过头再回来**——那一点点回弹就是"活着"的感觉。

### 3.3 逐字级联（stagger）

```tsx
{chars.map((c, i) => {
  const p = interpolate(t, [i * 3, i * 3 + 14], [0, 1], { clamp, easing });
  return <span style={{ opacity: p, transform: `translateY(${(1-p)*26}px)` }}>{c}</span>;
})}
```

**延迟多少**：一个字 2~3 帧。5 个字总时长 = 5×3+14 = 29 帧 ≈ 2 拍。  
超过 8 个字就按词组分组，不要逐字（会拖沓）。

### 3.4 运动模糊（Trail）

**这是"高级感"最直接的来源。** 元素快速移动时，真实镜头会拖影，而 CSS 动画不会。

```tsx
import { Trail } from "@remotion/motion-blur";

<Trail layers={7} lagInFrames={1} trailOpacity={0.42}>
  <FastMovingThing />
</Trail>
```

- `layers`：拖影层数，5~8 够用，多了会糊
- `lagInFrames`：每层间隔几帧，1 就够
- `trailOpacity`：拖影透明度，0.3~0.5

**注意**：Trail 会把子组件渲染 N 次（每次回退一帧），**开销是 N 倍**。  
只包需要模糊的那一个元素，不要包整个场景。

### 3.5 3D 翻转

```tsx
transform: `perspective(800px) rotateY(${(1 - p) * -92}deg) rotateX(${(1 - p) * 10}deg)`
```

三个要点：

- `perspective` 写在 transform 里（不是父元素），800~1400 之间
- 起始角度 **90° 左右**，不是 180°（180 会看到背面）
- 加一点点 `rotateX`，纯 Y 轴旋转看着像纸片

### 3.6 视差分层

三层以不同速度移动，大脑会自动解读成"有纵深"。

```tsx
const base = Math.sin((t / CYCLE) * Math.PI * 2) * 34;
layers.map(l => ({ transform: `translateX(${base * l.k}px)` }))
// k = 1 / 1.9 / 2.9，越近的层移动越快
```

**经验**：速度比 1 : 1.8 : 2.8 最自然，差值太小看不出纵深，太大像故障。

### 3.7 挤压拉伸（squash & stretch）

动画十二原则里最有效的一条。落地瞬间压扁、横向拉宽，**体积守恒**。

```tsx
const sq = interpolate(t, [14, 19, 26, 34], [1, 0.62, 1.12, 1]); // 压扁 → 过冲 → 回正
transform: `scale(${2 - sq}, ${sq})`,  // scaleX 和 scaleY 互补
transformOrigin: "50% 100%",           // 以底部为支点
```

`2 - sq` 保证 `scaleX × scaleY` 的乘积变化不大，看起来"没有凭空变大"。

### 3.8 光圈转场

```tsx
clipPath: `circle(${r}px at 50% 50%)`   // r 从 0 到覆盖全屏
```

适合"聚焦到某一点"的场景，比如从全景推到某个商品。

## 四、转场：用官方 `@remotion/transitions`

以前是自己写 opacity 叠化，现在有现成的，而且效果专业得多。

### 4.1 安装与基本用法

```bash
npm i --save-exact @remotion/transitions@4.0.536
# 注意：所有 @remotion/* 必须锁同一版本，去掉 ^
```

```tsx
import { linearTiming, springTiming, TransitionSeries } from "@remotion/transitions";
import { fade } from "@remotion/transitions/fade";
import { pushCut } from "@remotion/transitions/push-cut";
import { iris } from "@remotion/transitions/iris";

<TransitionSeries>
  <TransitionSeries.Sequence durationInFrames={128}><SceneA /></TransitionSeries.Sequence>
  <TransitionSeries.Transition
    presentation={pushCut()}
    timing={linearTiming({ durationInFrames: 8 })}
  />
  <TransitionSeries.Sequence durationInFrames={128}><SceneB /></TransitionSeries.Sequence>
</TransitionSeries>
```

### 4.2 适合卡点视频的四个预设

| 预设                | 效果          | 什么时候用               |
| ----------------- | ----------- | ------------------- |
| **`pushCut()`**   | 硬切 + 短暂闪白   | **最佳卡点转场**，鼓点上"砸"一下 |
| **`iris()`**      | 圆形遮罩从中心展开   | 聚焦、揭晓               |
| **`blurSlide()`** | 横向甩动 + 运动模糊 | 快速翻页、清单切换           |
| **`wipe()`**      | 滑动覆盖        | 稳重的过渡               |

还有：`fade` `slide` `flip` `clockWipe` `zoomBlur` `dreamyZoom` `filmBurn` `ripple` `crossZoom` `swap` `dissolve` `bookFlip`。

> `zoomBlur` / `dreamyZoom` / `filmBurn` 这些是 HTML-in-canvas 实现，效果很炫但**渲染更慢**，  
> 30 秒片子里用 1~2 次就够。

### 4.3 `Overlay`：在不改变时长的地方加效果

转场会**缩短总时长**（两个场景重叠），但 `Overlay` 不会——它只是在切点上叠一层东西。

```tsx
<TransitionSeries.Overlay durationInFrames={12}>
  <Flash />          {/* 闪光 / 光斑 / 音波可视化 */}
</TransitionSeries.Overlay>
```

**这是卡点神器**：切点那一帧叠一个 12 帧的白闪，视觉上"啪"一下，时长完全不变。

### 4.4 三条硬规则

1. 转场不能比前后任一场景更长
2. 两个转场不能相邻（中间必须隔一个 Sequence）
3. 转场和 Overlay 不能相邻（它们占同一个位置）

## 五、编排：让多个元素"有节奏地"出现

单个动效再好看，同时出现 5 个就是一团乱。编排决定"顺序"。

### 5.1 三种编排模式

| 模式     | 做法                  | 适合       |
| ------ | ------------------- | -------- |
| **级联** | 第 i 个延迟 `i × 3` 帧   | 列表、卡片墙   |
| **分组** | 每 3 个一组，组间延迟 8 帧    | 信息块      |
| **主次** | 主元素先出，辅助元素延后 6~10 帧 | 标题 + 副文案 |

### 5.2 卡点视频的特殊编排

**所有元素都要"落在拍上"，但不是同一拍。**

```
第 1 拍：图标
第 2 拍：数字
第 3 拍：标题
第 4 拍：补充句
```

这样每一拍都有新东西进来，观众的注意力被"喂"了四次，而不是一次性喂饱。

### 5.3 反例

```
❌ 5 个元素全部在 beatF(10) 出现 → 像一次性刷新，没有节奏
✅ 5 个元素分别在 beatF(10)~beatF(14) → 每一拍都有落点
```

### 5.4 切点那一帧必须有"主内容"落地

**这是实测踩出来的。** 场景切在 `barF(4)`，但主标题落在 `beatF(17)`（晚一拍），  
结果切点那 16 帧只有一个很小的标签，画面是空的——**加了闪白之后更明显，因为闪白把注意力引到了空帧上**。

正确的编排：

```
❌ 标签 beatF(16) → 标题 beatF(17) → 数据 beatF(18)
   切点（beat 16）只有标签，主标题晚一拍

✅ 标签 beatF(16) - 6 → 标题 beatF(16) → 数据 beatF(17)
   切点（beat 16）主标题已经落定，画面是满的
```

**规则**：

- 标签这类"小元素"提前 5~6 帧落定（跟着场景淡入一起出现）
- **主标题必须正好落在切点那一拍**
- 后续内容再逐拍跟上

> 判断方法：把播放头停在每个 `barF(n)` 上截图，看有没有"空帧"。  
> 有，就说明主内容晚了。

## 六、性能与坑

| 坑                     | 现象               | 解法                                                 |
| --------------------- | ---------------- | -------------------------------------------------- |
| `Trail` 包太大           | 渲染慢 3~5 倍        | 只包单个元素，不包场景                                        |
| 动画 `width` / `height` | 布局抖动，掉帧          | 改用 `transform: scale`                              |
| 动画 `top` / `left`     | 同上               | 改用 `translate`                                     |
| 同一元素多个 spring         | 互相打架，抖动          | 一个 spring 驱动多个属性                                   |
| `filter: blur()` 大面积  | 渲染极慢             | 用 Trail 或缩小范围                                      |
| 忘记 `clamp`            | 循环结束后继续外推，元素飞出画面 | `interpolate` 一定加 `extrapolateLeft/Right: "clamp"` |
| `Math.random()`       | 每帧不同，闪烁          | 用 `seeded()`                                       |

## 七、优先级：只有时间做三件事的话

1. **把淡入换成遮罩擦除** —— 成本最低，质感提升最明显
2. **把交叉淡化换成 `pushCut`** —— 卡点视频的转场正确解法
3. **给快速移动的元素加 `Trail`** —— "高级感"的主要来源

其他都可以后面再说。

| 抽哪一帧             | 看什么                  |
| ---------------- | -------------------- |
| 元素**刚开始动**的第 1 帧 | 有没有"起跑"的预备动作（还是突然出现） |
| 元素**动到一半**       | 有没有运动模糊（快速位移时）       |
| 元素**刚落定**的那帧     | 有没有过冲或挤压（还是硬停）       |
| **切点**那一帧        | 前后两个场景是不是都在（叠化透底）    |
