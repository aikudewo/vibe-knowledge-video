# 选题对接协议

> 用户给一个主题 ≠ 可以开工。
> 从「主题」到「成片」之间，有四次确认。跳过任何一次，返工概率超过 60%。

---

## 零、这条协议解决什么

**以前的错**：用户说「做个双11 的」，我直接开始写文案、搭组件、渲染。
结果是——方向对了是运气，方向错了就是 4 小时白干。

**现在的规矩**：主题进来，先走四步确认，**每一步都要用户点头才往下走**。

```
主题
 ↓
① 澄清（问 3~4 个问题）        ← 搞清"要什么"
 ↓
② 三版提案（三个不同的角度）    ← 让用户"选一个"
 ↓
③ 确认与修改（问要不要改）      ← 确认"就这样"
 ↓
④ 脚本先行（分镜表 + 逐句文案）  ← 确认"这么讲"
 ↓
⑤ 制作（写代码 / 配音 / 渲染）
```

**铁律**：**没有经过 ④ 的确认，不许开始写代码。**

---

## 一、第 ① 步：澄清（分两层，八个问题）

不要问「你想要什么样的视频」——用户答不出来。
要问**能直接选的问题**，而且**内容层和制作层都要问**。

### 1.1 为什么制作层必须问，不能"边做边定"

| 制作参数 | 一旦定了 | 中途改的代价 |
|---|---|---|
| **时长** | 分镜配比（14 小节 / 21 小节 / 30 小节） | 重排全部场景 |
| **BGM** | 整条节拍网格，所有时间点的源头 | **全片重做**（每个 `beatF()` 都变） |
| **比例** | 版式分区、字号、安全区 | 重排版式 |
| **角色** | 版式安全区（内容底边 ≤660） | 重排版式 |
| **字幕** | 文字大小和停留时长 | 逐句调整 |

> 这五项里，**BGM 和时长是"地基级"的**。地基定了才能画图纸，
> 所以必须在提案之前问清楚，而不是做完再问"要不要换个音乐"。

### 1.2 第一轮：内容层（3 问）

| # | 问题 | 选项 | 决定什么 |
|---|---|---|---|
| 1 | **这条的目的是？** | A 种草推荐（推荐具体商品）<br>B 科普解释（讲清一个道理）<br>C 观点输出（立一个态度）<br>D 清单盘点（给一份可照抄的名单） | 文案骨架。推荐要"看什么不看什么"，科普要"为什么"，观点要"冲突" |
| 2 | **有没有指定商品/品牌？** | A 有，我指定<br>B 没有，你按数据选<br>C 有几个候选，帮我筛 | 有指定 → 围绕它做对比；没有 → 按销量/增速/口碑选，多一轮确认 |
| 3 | **受众现在处在哪一步？** | A 还没想买<br>B 正在比价<br>C 已经下单，怕踩坑 | 决定"说服"还是"避坑"。C 阶段的人最爱看"别买什么" |

### 1.3 第二轮：制作层（5 问，附默认值）

| # | 问题 | 选项 | 默认 |
|---|---|---|---|
| 4 | **时长和比例？** | A 30s / 16:9<br>B 45s / 16:9<br>C 30s / 竖屏 9:16<br>D 60s / 竖屏 9:16 | **B（45s）** —— 能放下"细讲 + 避坑"，又不至于注水 |
| 5 | **BGM 怎么来？** | A 我发给你<br>B 你按情绪选一首<br>C 沿用上一条那首 | **C（沿用）** —— 系列片用同一首，观众一听就知道是你 |
| 6 | **要不要角色？** | A 有小人<br>B 纯文字 | **A（有）** —— 系列片的识别符号 |
| 7 | **字幕要不要烧进画面？** | A 烧进去（大字幕）<br>B 不烧，留白给平台字幕 | **A（烧）** —— 抖音 70% 是静音观看 |
| 8 | **发在哪个平台？** | A 抖音<br>B 视频号<br>C 小红书 | **A（抖音）** —— 决定首帧和封面构图 |

> 用户说"你定"的时候，直接用默认值，并在回复里写一句
> 「按默认走：45s 16:9 / 沿用上条 BGM / 有小角色 / 烧字幕 / 发抖音，有异议随时说」。

### 1.4 分两轮问，不要一次抛八个

**第一轮 4 个**：目的、有无指定商品、受众阶段、时长比例
**第二轮 4 个**：BGM、角色、字幕、平台

一次性抛八个问题会让人烦；分两轮，第二轮可以在提案里顺带确认。

### 1.5 提问的格式

用 **AskUserQuestion**，一次最多 4 个，每个 2~4 个选项，**第一个选项标注"推荐"**。

> ❌ 错误：「你想做什么风格的视频？」（开放题，用户懵）
> ✅ 正确：「这条是种草推荐，还是单纯科普？」（二选一，用户秒答）

> ❌ 错误：「BGM 你有什么想法？」（开放题）
> ✅ 正确：「BGM 是你发给我，还是沿用上一条那首？」（省事，且默认值合理）

### 1.6 澄清完要复述一遍

问完之后，用三行把结论复述出来，让用户确认无误：

```
收到，按这个走：
内容 · 种草推荐 / 不指定商品 / 受众在比价阶段
制作 · 45s 16:9 / 沿用上条 BGM / 有小角色 / 烧字幕 / 抖音
我出三版提案，10 分钟后给你。
```

**复述这一步很关键**——用户常常在选完之后才想起来"哦对了，时长要短一点"。
复述给了他第二次纠错的机会，成本比做完再改低得多。

## 二、第 ② 步：三版提案（最关键的一步）

澄清完之后，**不要只给一个方案**。给三个**真正不同**的版本，让用户选。

### 2.1 三版必须"不同"，不是"三个措辞"

四个差异维度，每版至少换一个：

| 维度 | 可选项 |
|---|---|
| **视角** | 从人出发（你的生活） / 从物出发（这件东西） / 从数据出发（大盘趋势） |
| **结构** | 清单 / 对比 / 避坑 / 故事 / 时间线 / 问答 |
| **立场** | 推荐（该买） / 反推荐（别买） / 中立观察（看看别人怎么买） |
| **切口** | 价格 / 情绪 / 数据 / 身份（独居、租房、新手爸妈） |

### 2.2 每版必须写清六件事

```
【版本 A · 名称】
切入角度：一句话说清"从哪儿切"
一句话主张：≤20 字，就是结尾金句
内容骨架：分几段，每段讲什么
钩子（前 3 秒）：第一句原话
画面设想：文字 / 卡片 / 角色 / 图表
差异点：和 B、C 到底差在哪
风险：这版最可能翻车的点

【版本 B · ...】
【版本 C · ...】

我的推荐：X
理由：……（说人话，不要客套）
```

### 2.3 范例：双11 这个选题，三版应该是这样

如果用户说「做个双11 家居的」，正确的三版提案：

**版本 A · 时机型（最终采用的就是这版）**
- 切入角度：从"什么时候买"切，不做品类科普，只做时机判断
- 主张：双 11 不是买得多，是买对那几样
- 骨架：钩子 → 五类总览 → 细讲两类 → 快讲三类 → 避坑三类 → 清单表 → 收尾
- 钩子：双 11，别急着清空购物车 / 真正该买的只有五类
- 画面：5 张 3D 卡片 + 小人 + 24h 式清单表
- 差异：唯一一版有"避坑"段落的
- 风险：时效性强，过了 10.20 开头就要改

**版本 B · 反推荐型**
- 切入角度：只讲"别买什么"，正向推荐只在最后一句带过
- 主张：双 11 最大的坑，是把便宜当成理由
- 骨架：钩子（三个智商税品类）→ 逐条拆解为什么不该买 → 什么情况下才值得买 → 收尾
- 钩子：这三样，双 11 买就是亏
- 画面：红色警示色 + 打叉动画 + 价格对比
- 差异：立场完全反过来，情绪更强，评论率更高
- 风险：负向内容，和"暖调家居"的账号调性有冲突，可能掉粉

**版本 C · 人群型**
- 切入角度：按"独居 / 新婚 / 有娃"三种人分开推荐
- 主张：同一个双 11，三种人该买的东西完全不一样
- 骨架：钩子 → 三张人群卡 → 每类人给 3 件 → 交叉对比 → 收尾
- 钩子：独居的人，双 11 别买这些
- 画面：三个人物剪影 + 分栏布局
- 差异：从"品类"换成"人群"，个性化强，适合做系列
- 风险：信息密度大，45 秒塞不下三类人，可能要 60 秒

> 这三版的结构、立场、切口全都不同。用户选哪版，后面就是完全不同的片子。

## 三、第 ③ 步：确认与修改

用户选完之后，**不要立刻开工**。再问一次：

```
选 A 的话，有两点想跟你确认：
1. 「避坑」这段要不要保留？它是这版最有转发欲的部分，但会让调性偏冷。
2. 五类里"换季收纳"单价太低（100-200），要不要换成客单价更高的品类？

要不要改？改哪部分都可以说。
```

### 可改的颗粒度（明确告诉用户）

| 层级 | 改起来 | 说明 |
|---|---|---|
| 主张 / 金句 | 快 | 改一句话，不动结构 |
| 品类 / 清单项 | 中 | 要重排分镜，可能影响时长 |
| 结构 / 场景顺序 | 慢 | 等于重做提案 |
| 语气 / 用词 | 快 | 全局替换 |

> 这一步的价值：**在成本最低的时候改**。
> 改文案 5 分钟，改结构 1 小时，改成片 4 小时。

## 四、第 ④ 步：脚本先行（最重要的交付物）

**先给脚本，不给代码。** 脚本要能让用户"看见"成片。

### 脚本必须包含

1. **分镜表**：小节 / 帧 / 画面描述 / 逐句文案
2. **钩子**：前 3 秒的每一句话
3. **金句**：哪两句是截图位
4. **节奏说明**：每个场景占几小节，为什么
5. **画面备注**：哪里用卡片、哪里用图表、小人站在哪

### 脚本格式

```markdown
## 分镜脚本 · 《标题》

【参数】112.9 BPM / 21 小节 / 45s / 16:9

| 小节 | 画面 | 文案 | 备注 |
|---|---|---|---|
| 0 | 小字标签 | 10.20 · 双 11 现货开售 | 时效信息 |
| 1 | 主标题第一行 | 双 11，别急着清空购物车 | 96px 宋体 |
| 2 | 主标题第二行 | 真正该买的只有五类 | 朱红 |
| ... | | | |

【钩子】双 11，别急着清空购物车 / 真正该买的只有五类
【金句】双 11 不是买得多 / 是买对那几样
【节奏】钩子 2 小节，细讲各 3 小节，快讲 3 小节，避坑 2 小节，清单 3 小节，收尾 3 小节
```

### 确认话术

```
脚本在上面，三个地方想请你确认：
1. 五类商品的排序，按"涨得最凶→最便宜"排，要不要调？
2. 避坑只放三类，够不够？
3. 收尾金句是这两句，要不要换？

确认没问题我就开始做。
```

## 五、贯穿原则：先搜再说

> 记忆会过期，搜索结果不会。
> **凡是"会变"的东西，一律现搜，不靠印象。**

### 5.1 六类必须现搜的信息

| 类型 | 举例 | 半衰期 | 不搜的后果 |
|---|---|---|---|
| **平台规格** | 视频尺寸、码率、时长上限、审核红线 | 半年~1 年 | 片子做完传不上去 |
| **时间节点** | 大促起止、节日、活动档期 | 每年变 | 文案写错日期 |
| **价格与折扣** | 到手价、满减规则、补贴 | 1~2 周 | 说错价格，评论区翻车 |
| **热梗热点** | 流行语、事件、二创 | 1~2 周 | 蹭到过期的梗 |
| **行业数据** | GMV 增速、渗透率、品类涨跌 | 季度 | 论据过时 |
| **工具与 API** | 库的版本、接口变更、新能力 | 每月 | 用了已废弃的写法 |

### 5.2 三个层次，缺一不可

```
第一层 · 选题层：这个题现在有人在讲吗？讲到什么程度了？（05 已覆盖）
第二层 · 事实层：我要引用的数字、时间、规格，现在还准吗？
第三层 · 判断层：现在做还来得及吗？窗口还剩几天？
```

> 大多数人只做第一层（看看别人怎么讲），漏掉第二层就会说错事实，
> 漏掉第三层就会做出"晚了三天"的片子。

### 5.3 实例：双11 那条，如果没搜会怎样

| 如果凭印象写 | 实际（搜出来的） |
|---|---|
| 「11 月 11 日，双 11 当天」 | 淘宝 10.15 预售、**10.20 20:00 现货开售**、11.10 终极狂欢 |
| 「床品便宜，值得买」 | 床品寝具 GMV **涨近 2 倍**（有数据支撑） |
| 「灯具也可以看看」 | **灯具是淡季回落品类**，双 11 反而贵（反常识点） |

三条全错。而且第三条错得最值钱——**它本来是全片最有说服力的段落**。

### 5.4 搜索结果怎么用

**必须标注时间和来源**：

```
✅ 「2026 双11，淘宝 10 月 20 日 20 点现货开售（据 10 月 16 日平台公告）」
❌ 「双11 一般都在 11 月」
```

**冲突时取最新 + 最权威**：官方公告 > 行业报告 > 媒体报道 > 自媒体。

**搜不到就说搜不到**：

```
✅ 「这个品类的具体增速我没查到可靠数据，建议这版先不引用数字，改成体感描述」
❌ 编一个"增长 300%"
```

> 编数据的代价不是"不准"，是"被评论区指出来之后，整条片子的可信度归零"。

### 5.5 什么时候可以不搜

| 情况 | 处理 |
|---|---|
| 纯观点、纯情绪表达 | 不用搜，本来就无需求证 |
| 用户明确给了事实和数字 | 不用重复搜，但可以在脚本里标一句"数据来自你提供" |
| 常识性内容（"冬天冷"） | 不用搜 |
| **其他一切涉及具体数字、时间、规格、价格的** | **必须搜** |

### 5.6 搜索的产出要落到文档里

搜完不是"我知道了"，要把结论写进脚本或提案，并注明来源。

在提案里加一行：

```
【事实依据】床品 GMV 涨近 2 倍（来源：CID 电商选品趋势 10.9-10.15 周报）
```

这样用户能判断这个数据可不可信，也知道如果数据更新了该改哪里。

## 六、贯穿全程：建设性建议（这是加分项）

用户给主题时，**除了问问题，还要给判断**。不是"你想怎么做"，而是"我建议这么做，因为……"。

### 每次至少给这五条里的三条

| 维度 | 要回答的问题 | 双11 案例 |
|---|---|---|
| **内容延伸性** | 这个选题能做成系列吗？后面 3 条是什么？ | 双11 → 双12 → 年货节，可以做成"大促选品"系列 |
| **热点关联度** | 现在蹭有没有窗口？风险在哪？ | 10.20 是现货开售当天，窗口只有 24 小时，明天就凉 |
| **竞争饱和度** | 同选题有多少人在做？我们的差异在哪？ | 双11 攻略泛滥，但"按品类涨跌排"的角度没人做 |
| **账号匹配度** | 这个选题符合账号调性吗？会不会掉粉？ | 家居号做"避坑"合适，做"比价"就变成导购号了 |
| **时效与半衰期** | 这条片子能活多久？ | 时效型 3 天，观点型 3 个月，清单型 1 年 |

### 建议的写法

```
先说三个判断：

1. 这个选题现在做，窗口只有 24 小时（今晚 8 点开售），明天发效果减半。
2. 双11 攻略已经泛滥，但都是"推荐什么"，没人做"按品类涨跌排"。
   我建议从这个角度切，差异明显。
3. 这条能延伸成系列：双11 → 双12 → 年货节，用同一个模板换数据就行。

所以我的建议是：今天发，走"涨跌"角度，做成系列第一条。
```

> **建议要有立场**。说"都可以"等于没建议。

## 七、什么时候可以不问

协议不是死规矩。以下三种情况可以直接干：

| 情况 | 处理 |
|---|---|
| 用户已经给了明确指令（"照上一条的结构，换个主题"） | 跳过 ①②，直接从 ④ 脚本开始 |
| 用户明确说"你决定" | 跳过 ①②，但 ④ 脚本必须给 |
| 修 bug、改一个词、调一个颜色 | 直接改，不用问 |

**但有一条永远不能跳**：**脚本先审**。哪怕是改一句话，也要说清楚改成什么、在哪一段。

## 八、速查卡（贴在显眼处）

```
用户给主题
  ↓
❌ 不要直接写代码
  ↓
⓿ 先搜（凡是会变的都要搜）
   平台规格 / 时间节点 / 价格 / 热梗 / 行业数据 / 工具版本
   → 搜完标注来源和时间
  ↓
① 澄清（分两轮，共 8 问）
   第一轮 · 内容层：目的 / 有无指定商品 / 受众阶段 / 时长比例
   第二轮 · 制作层：BGM / 角色 / 字幕 / 平台
   → 复述一遍结论，让用户确认
  ↓
② 给三版提案（视角·结构·立场·切口 至少换一个）
   + 我的推荐 + 理由 + 事实依据
  ↓
③ 问"要不要改"，说清可改的颗粒度
  ↓
④ 出脚本（分镜表 + 逐句文案 + 节奏说明），等确认
  ↓
⑤ 才动手
```
