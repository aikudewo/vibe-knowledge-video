# AI 交接说明书

> 这个包是给**接手做片的 AI** 看的，不是给读者看的。
> 用法：把整个文件夹丢给另一个 AI，然后**复制下面第 0 节那段话**发给它。
>
> 如果你是人，只想自己上手：读 `README-先读我.md`，这份可以跳过。

## 第 0 节 · 复制这一段，粘给接手的 AI

> 下面的引用块就是完整 prompt，直接复制。

> 你接手一个已经在跑的短视频生产项目。先别动手，按顺序做完四件事，然后向我复述。
>
> **项目是什么**：用 Remotion（React 写视频）生产抖音知识科普短视频，每支 45 秒 / 1920×1080 / 30fps。
> 账号调性是暖米白纸感、克制、有书卷气，不要网络流行语和感叹号。内容偏家居 / 生活方式 / 身体与习惯类知识。
>
> **资料在哪**：这个文件夹里有 16 份 md 文档（编号 `00`–`12`，`00` 是主文档）、6 个 Python 工具、25 个 Remotion 模板组件、1 套要安装的技能、1 个完整案例。**没有**成片 mp4 和 BGM，那些要自己准备。
>
> **第一步，读这四份，按顺序**：
> 1. `00-工作流总览.md` —— 全流程、三道闸门、交付标准。其它文档都是它的补充。
> 2. `03-避坑清单.md` —— 31 条踩过的坑。这是这个包里最值钱的一份。
> 3. `MAC-适配.md` —— 环境差异和验证清单。
> 4. `模板/Dazi45.tsx` —— 当前质量基准。读它的开头注释，那里写了整支片的架构。
>
> **第二步，跑验证清单**（`MAC-适配.md` 第四节，4 条命令），证明工具链是通的。
> 跑不通就停下来说哪里不通，不要硬往下做。
>
> **第三步，读一遍 `项目/大字理论-纸感版/`**（脚本 + 验收报告 + 封面）。
> 这是「一支合格的片长什么样」的样本，脚本长什么样、验收数字写在哪、封面什么版式，都在里面。
>
> **第四步，向我复述**：你理解的生产流程（几个阶段、几道闸门）、五条不能破的规矩、以及这个包的默认交付标准（时长/比例/声音/平台）。
> 我确认之后才算接手完成。**复述之前不要写任何代码。**
>
> **五条不能破的规矩**（破了返工概率 > 60%）：
> 1. 全程一条镜头，0 次硬切。要换风格就换光，不要换镜。
> 2. 每屏至少三层：主体（图表/表格/户型图/公式）+ 数据 + 注释。只有大字的一屏，删掉。1080p 下正文 ≥ 26px、注释 ≥ 20px。
> 3. 先出 10 秒参考片给我审，过了才做整片。改脚本 5 分钟，改成片 4 小时。
> 4. 交付前跑 `工具/check_video.py`，PASS 之后**还要从成片抽 4～6 帧人眼看**。PASS 只证明指标达标，不证明构图上没打架、段落之间没空拍。
> 5. 发抖音前跑 `工具/check_words.py`，CRITICAL 必须清零。违禁词藏在 21px 注释行和"事实陈述"里，肉眼审不出来。
>
> **跟我配合的方式**（这几条比技术更重要）：
> - 我给你主题后，**不要直接开工**。先问清内容层和制作层的问题（目的、受众、时长、BGM 谁给、要不要角色、发哪个平台），复述一遍让我纠错，再给三版**真正不同**的方案（视角/结构/立场至少换一个）附你的推荐，我选定后先出脚本给我看，确认了才做片。
> - **时长和 BGM 是地基**，必须在提案前定死，不能边做边定。
> - 我说"你定"时用默认值：45s / 16:9 / 沿用上一条 BGM / 有小人角色 / 烧字幕 / 发抖音，并在回复里写明你用了默认值。
> - **凡是"会变"的东西一律现搜**：平台规格、时间节点、价格、行业数据、工具版本。搜完标来源和时间，搜不到就说搜不到，**不要编数字**。
> - **文案不做营销**：只写「一个事实开场 + 内容 + 金句」。不借势平台趋势、不提大促节点、不用种草词话题、不写运营话术。数字出处放评论区。文案**直接贴在对话里**给我（标题/正文/话题三段），不要建 md 文件。
> - **所有视频不加人声配音，只放 BGM**，画面字幕保留。
> - 建议要有立场。说"都可以"等于没建议。
>
> 现在开始第一步。

## 三、六个最容易误判的地方

这六条是这个包存在的主要理由。不看这几条，前面读的都会白读。

### 1. `check_video.py` 给 PASS，不等于能交付

验收器只测**墨量和运动量**。它看不见：
- 两个元素压在一起（文字压字、卡片压人物）
- 段落之间留了 20 帧空拍，画面只有一个人站着
- 元素从第 0 帧就画在世界上，镜头一扫到就露馅

这三类问题**只有人眼抽帧能抓**。已定稿的四版片子里，三版的致命伤是抽帧发现的，
脚本一次都没报。

### 2. `check_words.py` 扫 `.md` 会误报

文档里写着规则条文本身（"不出现康复/治疗/改善/缓解"），扫 md 会把条文当成命中。
**判据只认 `.tsx`。** 扫 md 的结果只用来提醒"这段文案里有没有藏词"，不当作硬指标。

### 3. 帧差高不等于好，但帧差低一定差

帧差均值 < 0.5 就是 PPT。但 1.3 也不代表好看——它可能只是镜头一直在推。
**帧差要看的是"每一段都有变化"，不是总均值。** 停留段每帧完全一样（静止帧超 2%）
就是 6 秒冻屏，观众划走。

### 4. 亮部比例不能跨片直接比

有暗场的片子亮部会明显偏高（17% vs 8%），这是正常的。
**跨片比较必须同分辨率**，而且不要把有暗场的和全程暖白的放一起比。

### 5. 抽帧必须从成片抽，不能从渲染器静帧抽

静帧和成片之间还隔着编码。观众看到的是成片。用：

```bash
ffmpeg -y -i out/x.mp4 -ss 20.0 -frames:v 1 out/f20.png -loglevel error
```

### 6. 长镜里，元素透明度挂"镜头什么时候到"，不是"话什么时候说"

两者经常差 100 帧以上。挂错了就会出现大段空墙——话在说，画面是空的。

## 四、术语表

接手时会遇到这些词，都是这个项目内部的叫法：

| 词 | 意思 |
|---|---|
| **段 / 站** | 一段文案 = 一个站。人物走到这一站停住，讲完再走 |
| **闸门 A/B/C** | 三道人工确认点：脚本、10 秒参考片、验收 |
| **节拍网格** | 从 BGM 算出 BPM 和首拍，得到"一拍 = 多少帧""一小节 = 多少帧"，所有时间点卡在上面 |
| **世界层 / 屏幕层** | 世界层放家具、图表卡、人物（跟着镜头动）；屏幕层放标题、脚注、金句（不跟镜头动，否则会被推出画外） |
| **墨线抖动** | 世界层每帧加 ±0.7px 的平滑正弦位移，模拟手绘线条的呼吸。**漏掉这一项停留段就是冻屏** |
| **压白 / 压黑** | 用一层近乎不透明的白/黑盖住整个画面做风格切换。压白要往更亮的暖白推（`#fdf8ec`），不能往纸色推，否则整帧变均匀色块 |
| **换光不换镜** | 风格变换的唯一合法做法：镜头不动，只改光。硬切是本项目的禁区 |
| **招牌镜头** | 一支片里最有辨识度的那一屏。封面主体必须从这里挑，不能另画一个 |

## 五、给人看的：怎么纠它

如果你发现它跑偏了，这三句话最有效：

| 症状 | 说这句 |
|---|---|
| 做出来像 PPT，一屏只有大字 | 「每屏要三层：主体 + 数据 + 注释。现在只有字。」 |
| 自己闷头做完了整片才给你看 | 「先给我 10 秒参考片，我点头你再做整片。」 |
| 文案写得像广告 | 「不要提这些，就正常做知识分享就行。」 |
| 数字对不上 / 出处不明 | 「这个数字哪来的？搜一下，标来源和时间。」 |
| 交付了但它自己没看过 | 「从成片抽 6 帧发我。」 |

## 六、这个包的边界

**它能给你**：一套验证过的流程、一个当前质量基准、31 条踩坑记录、一套可跑的验收工具。

**它不能给你**：
- 成片 mp4、BGM 音频、参考视频（体积大、每支片不同，按需自己放）
- 现成的选题。选题每次都要现搜现判断
- 保证不返工。这套流程的作用是**把返工提前到脚本阶段**，不是消除返工

**一个诚实的提醒**：这套流程是为一支 45 秒长镜纸感知识片打磨出来的。
换成长视频、换成分镜剪辑、换成真人出镜，`00` 里的阶段配比要重新算，
但 `03` 里的 31 条坑大部分仍然成立——那些是画面和观众的规律，不是这一种片型的规律。
