## 零、这一版改了什么（v1 → v2）

v1 那套是「30 秒 / 五个场景 / 场景间硬切」的思路，做完霓虹版之后发现一个死结：
**线稿风格 + 硬切 = 一定像 PPT**。v2 是把这个死结从结构上拆掉之后的版本。

| 环节 | v1 的做法 | v2 的做法 | 为什么改 |
|---|---|---|---|
| 镜头 | 5～9 个场景，场景间硬切 | **全程一条镜头，0 次硬切** | 切点就是 PPT 换页感 |
| 主体 | 每屏重新排版 | **一个小人从头走到尾**，观众有视觉锚点 | 满屏文字，眼睛没落点 |
| 信息 | 一屏一屏铺 | **只在小人停住的窗口里出信息** | 走的时候出字，眼睛跟不上 |
| BGM | 从 drop（副歌）切 | **用户给的曲子从 0:00 播**，不从高潮开始 | 从高潮起，前面全废 |
| 画面静止 | 不检查 | **墨线抖动**，静止帧 ≤ 2% | 停留段每帧一样 = 冻屏 = PPT |
| 交付 | 渲完就发 | **10 秒参考片先审 + 验收器 + 人眼抽帧** | 4 小时白干 vs 10 分钟返工 |

v1 的文档（01/05/07/09 等）讲的方法仍然有效，但**结构层以本文为准**。

### v2 → v2.1（2026-10-23，做完第三条纸感片之后补的）

结构没动，补的全是**「可读性」和「构图冲突」**这一层：

| 环节 | v2 的做法 | v2.1 的做法 | 为什么改 |
|---|---|---|---|
| 数字字体 | 跟着标题用宋体 | **一律 sans + bold** | 宋体数字笔画细、字距宽，46px 只有 sans 36px 的视觉重量 |
| 文字 alpha | 次级 0.48 / 主 0.72 | **次级 ≥0.64 / 主 ≥0.84** | 0.48 在纸底上等于浅灰 |
| 底部字幕 | 34px | **40px** | 手机屏上 34px 只剩 12pt 视觉 |
| 渲染编码 | 默认参数 | **`--crf=16 --pixel-format=yuv420p --color-space=bt709`** | 默认 `yuvj420p` 2.8 Mbps，暗部糊 |
| 地板通道 | 必须清空 | **可以放家具，把家具渲染在人之上** | 侧视图里渲染顺序本身就是纵深 |
| 信息卡注释 | 只要密度高就行 | **必须和主体同语义** | 塞不相干的东西 = 语义串味 |
| 收尾压白 | 靠 `veil` 一层盖 | **深色元素单独给 `opacity`** | 白纱降的是对比度，不是存在感 |
| 抽帧 | 抽一轮 | **改字号/坐标/渲染顺序后重抽** | 上一轮的帧全部作废 |

> 触发点是用户一句「文字不够清晰」。量完发现对比度 7.7–13.9:1，**颜色没问题**，
> 问题在字号、alpha、字体、码率四项叠加。详见 `12` 的 2026-10-23 复盘。

### v2.1 → v2.2（2026-10-26，片子被限流之后补的）

结构也没动。补的全是**「片子做完了、也过关了，但发不出去」**这一层：

| 环节 | v2.1 的做法 | v2.2 的做法 | 为什么改 |
|---|---|---|---|
| 违禁词 | 靠肉眼审 | **`check_words.py` 跑一遍，CRITICAL 清零** | 违禁词藏在 21px 注释行和"事实陈述"里，肉眼四轮都没看见 |
| 话题 | 想到什么打什么 | **只用内容词，不用种草词** | `#家居好物` 会把内容推进电商流量池 |
| 文案立场 | 讲一个商品 | **讲一件事** | 产品史读起来像带货 |
| 封面 | **没有这一步** | **独立出 1080×1440** | 视频首帧是 16:9，在列表里两边被裁 |
| 限流排查 | 一条一条猜 | **横向对比找对照组** | 三条片子同 BGM，基准片没事 → 直接排除 |

### v2.2 → v2.3（2026-10-26，用户要「更大胆」之后补的）

这是第一次动**宏观视觉**。前面几版补的都是细节（可读性、合规），这一版补的是
**「45 秒看下来像不像同一个世界」**。

| 环节 | v2.2 的做法 | v2.3 的做法 | 为什么改 |
|---|---|---|---|
| 整片视觉 | 八段同一张米白纸 | **按内容分世界：暖白 → 暗场 → 暖白** | 帧内信息够 ≠ 整片不单调，八段同色等于一张长图 |
| 风格切换 | 只能靠硬切 | **换光不换镜**，镜头一条到底 | 硬切会破「长镜」这个片型 |
| 主体 | 全部平面 | **关键段落做成斜的三维板** | 平面到三维是免费的表现力，且不用 CSS 3D |
| 线条 | 全程墨线抖动 | **抖动跟着内容开关** | 抖动=人手，不抖=机器，一条线也有语义 |
| 交接 | 上一段退了再上下一段 | **必须接上，不留空拍** | 黑底上只剩一个小人 = 空屏，验收会抓 |
| 封面 | 每片另画一个主体 | **从片子里挑招牌镜头** | 封面和正片是同一支片，主体不该是两回事 |

> 触发点是用户一句「不同的内容可以尝试更大胆的动效、背景、风格变换，
> 例如从白转到黑，由平面到三维」。详见 `03` 第 31 条。

> 触发点是用户一句「被限流了」，加一句「前面没事，就最近两条有问题」。
> 第二句是**对照实验**，把十几种可能一次砍到剩两个。
> 最直接的病灶是数据卡 21px 注释行里的「小红书」——四轮抽帧都没看见。
> 详见 `12` 的 2026-10-26 复盘。

## 一、这套流程适合做什么

| 适合 | 不适合 |
|---|---|
| 知识科普、观点输出、清单盘点类短视频 | 真人出镜、实拍素材 |
| 需要精确卡点、批量生产同一风格的系列片 | 需要复杂转场特效的片子 |
| 文案为主、画面为文字服务的口播型内容 | 强叙事、需要分镜绘制的故事片 |
| 一个空间 / 一个系统里能走完的题目 | 话题本身没有物理场景（纯抽象概念） |

核心思路：**把画面写成代码**。颜色、字号、出现时机全是变量，改主题只改常量，不用重做设计。

> **选题自检**：能不能想象出一个小人在一个空间里走动、停在四个地方？
> 能 → 长镜版好做。不能 → 退回 v1 的卡片版，或者换题。

## 三、阶段详解

### 阶段 0 · 选题对接（拿到主题别急着动手）

**主题是起点，不是指令。** 从「用户说一个主题」到「开始写代码」之间，有四次确认：

```
主题 → ⓿ 先搜 → ① 澄清 8 问 → ② 复述结论 → ③ 三版提案 → ④ 脚本先审
```

- **⓿ 先搜**：凡是"会变"的东西一律现搜——平台规格、时间节点、价格、热梗、行业数据、工具版本。
  搜完标注来源和时间。搜不到就说搜不到，**不要编数字**。
- **① 澄清分两轮共八问**
  - 内容层：目的是种草还是科普？有无指定商品？受众在比价还是怕踩坑？
  - 制作层：**时长与比例？BGM 谁给？要不要角色？字幕烧不烧？发哪个平台？**
- **② 复述一遍结论**，让用户二次纠错（这一步拦掉的错最多）
- **③ 给三版真正不同**的方案（视角 / 结构 / 立场 / 切口 至少换一个），附推荐和理由
- **④ 出脚本先审**，确认后才写代码

> **制作层是地基**：时长决定分镜配比，BGM 决定整条节拍网格，角色决定版式安全区。
> 这三样必须在提案之前定，做完再改等于重做。

**用户说"你定"时的默认值**：45s / 16:9 / 沿用上一条 BGM / 有角色 / 烧字幕 / 发抖音。
默认值要在回复里写明，不能默默套用。

每次给主题还要附**三条以上建设性判断**：内容延伸性、热点关联度、竞争饱和度、账号匹配度、时效半衰期。

> **例外 · 文案类需求**：用户只说"文案"，不要给三版营销切口、不要建 md 文件、
> 不要分析。直接按 **标题 / 正文 / 话题** 三段贴在对话里。
> 内容只写「一个事实开场 + 内容 + 金句」，不借势平台趋势、不提大促节点、不写运营话术。

完整协议见 `08-选题对接协议.md`。

---

### 阶段 1 · 选题拆解

把选题拆成四个格子，**填不满就说明选题太抽象，要往下切一层**：

| 格子 | 家居篇 | 深睡自由 |
|---|---|---|
| 人群 | 25~35 岁独居 | 睡不好的成年人 |
| 场景 | 下班回家 | 夜里躺在床上 |
| 冲突 | 看得见 vs 看不见 | 以为是一张床 vs 其实是一个系统 |
| 四个可量化对象 | 椅子灯床品锅 | 光 / 声 / 温 / 压 |

方法见 `05-选题研究与爆款文案.md` 第一节。

---

### 阶段 2 · 检索与数据台账

去抖音、小红书、B站、微博搜同选题的高赞内容，**重点看开头第一句和最高赞评论**，不是看点赞数。

同时建**数据台账** `项目/片名-版本/数据.md`：每个要上屏的数字，都写清来源、时间、可信度分级。

| 级别 | 含义 | 能不能上屏 |
|---|---|---|
| ★★★ | 官方标准、学术论文、政府统计 | 直接上 |
| ★★ | 权威媒体转述、行业报告 | 上，但要写清口径 |
| ★ | 自媒体、二手转引 | 不上屏，或者改成定性表述 |

台账里还要有一节「**不用的数字**」——查到了但口径不清、或者太吓人的，写清为什么弃用。
这样下次不会又把它翻出来。

---

### 阶段 3 · 一句话主张

先写死一句话，全片都为它服务。这句话最后会变成结尾金句。

- 家居篇：**钱花在看不见的地方，生活会在看得见的地方还给你。**
- 深睡自由：**白天向外消耗，夜里向内修复。**
- 判断标准：能当封面大字、能被截图转发、不超过 20 个字。
- 它同时要和**开头第一句首尾同构**——开头是它的问法，结尾是它的答法。

---

### ◆ 闸门 A · 脚本先审

产出 `项目/片名-版本/脚本.md`，里面必须有：

- 逐段文案（短句，≤15 字）
- 每段的主体是什么（图表 / 表格 / 户型图 / 公式），不能只有大字
- 时长配比（按小节算，不按秒）
- 角色动作清单（只有四个动作就够，不要设计复杂表演）

**用户点头之前不写代码。** 改脚本 5 分钟，改成片 4 小时。

---

### 阶段 4 · 定 BGM

**顺序很重要**：先有音乐，分镜才有骨架。

#### 4.1 用哪首

| 情况 | 做法 |
|---|---|
| 用户给了曲子 | **就用那首，从 0:00 开始**。不许自己换、不许从高潮切 |
| 用户没给 | 从 `素材/BGM/` 里选，或者问 |
| 需要缩短 | 从**开头**截，保留前奏，不要从 drop 起 |

> **2026-10-22 用户明确要求**：`bgm要使用那个一开始给你的那个从头开始播放，不用从高潮开始，
> 一定要跟随画面卡点，跟随主体动作或者动效卡点`
>
> v1 文档里「从 drop 切、一开口就是满能量」那条**作废**。
> 从高潮起的后果：前 17 秒的铺垫全丢了，片子没有起势，观众一进来就是满的，反而没有对比。

#### 4.2 怎么切

```bash
# 45 秒从 0:00 截，加淡入淡出，归一化到峰值 0.90
ffmpeg -ss 0 -t 45 -i "素材/BGM/千年之后_氛围版_完整.m4a" \
  -ac 2 -ar 48000 -c:a pcm_s16le public/bgm-qn45.wav
```

- 开头 0.12s 淡入（压掉第一拍的爆音）
- 结尾 0.9s 淡出（硬收的歌必须做，否则最后一声"咔"）
- 归一化峰值 **0.900**、RMS **0.318** 左右
- 给 Remotion 用 **wav**，源文件（m4a/mp3）保留在 `素材/BGM/`

#### 4.3 验证是不是同一首、同一段

换过采样率或格式之后，用互相关确认没截错位置：

```python
# 相关系数 > 0.95 才算同一段
np.corrcoef(a[:n], b[:n])[0, 1]
```

深睡自由实测：`0.990 @ 0.00s`（其他候选 0.325 / 0.083 / 0.083），确认是同一首、同一起点。

### 阶段 5 · 算节拍，得到帧网格

```bash
# 1. 转单声道 wav 给分析脚本
ffmpeg -i public/bgm-qn45.wav -ac 1 -ar 22050 草稿/audio/bgm.wav

# 2. 算 BPM + 首拍相位
python3 工具/analyze2.py
```

拿到三个数：**BPM、首拍时间、音乐实际结束时间**。

《千年之后》实测：

```
BPM      112.8
首拍相位  0.01s
一拍     0.5319s = 15.957 帧 @30fps
一小节   4 拍 = 63.83 帧
45 秒    = 1350 帧 ≈ 21 小节
```

代码里写成函数，**不要手写帧号**：

```ts
const BEAT = 0.5319 * 30;              // 15.957
const B = (n: number) => 1 + n * BEAT;  // 第 n 拍落在第几帧
```

> **⚠️ 节拍会越到后面越飘**：把"一拍 16 帧"当固定值，56 拍之后就差 2.8 帧。
> 每一拍都要从相位算，不要累加。

详细原理见 `02-BGM卡点方法.md`。

### 阶段 6 · 排分镜（长镜节奏）

#### 6.1 核心：走 → 停 → 讲 → 走

**全程一条镜头，0 次硬切。** 主角从起点出发，经过各站，每站停住讲完再走，最后收尾。

| 规则 | 做法 |
|---|---|
| 镜头跟着主角 | 走时动，停时停（停留段只留 0.005–0.01 缓推，不是完全不动） |
| 信息只在停住时出 | 走的时候不出新信息，观众眼睛有落点 |
| 站卡在小节线 | 站位起点落在 `63.83 × n` 帧上 |
| 段落内的点卡在拍上 | 一拍 15.957 帧 |
| 元素入场 | 淡入 + 0.94→1 缩放 + 16px 上浮，12 帧。**不要硬切** |
| 面板退场 | 早于下一段进场 **8–10 帧**，否则残影压在新段和人物身上 |

深睡自由实测的站位帧：`128 / 288 / 480 / 672 / 864 / 1056`，
分别是第 `26 / 58 / 96 / 135 / 174 / 213` 小节的线——全部落在小节线上。

#### 6.2 世界层 / 屏幕层必须分开

| 层 | 放什么 | 为什么 |
|---|---|---|
| **世界层**（在 `camT` 变换里） | 家具、图表卡、人物、地面 | 会跟着镜头走，有空间感 |
| **屏幕层**（在 `camT` 外面） | 标题、脚注、清单卡、金句 | 永远钉在画面上，不会被镜头推出画外 |

> 这一条是踩出来的：标题放在世界层，镜头一推，标题就被切掉一半。

#### 6.3 地板通道必须空着

侧视图**没有纵深**。任何落地的物件，都会被走过去的人穿模。

- ❌ 落地书桌、落地绿植、茶几、落地灯
- ✅ 墙上的搁板、桌上的东西、挂画（人从前面走过是合理的）

### 阶段 6.5 · 风格变换（2026-10-26 新增，v2.3）

**什么时候用**：内容本身有两个世界。比如「人的活法」对上「机器的算法」、
「过去」对上「现在」、「具体」对上「抽象」。**没有这层对立就别硬做**，
换光是手段不是目的，硬换只会显得花。

**做法一句话：三个世界，一条镜头。风格变换靠换光，不靠剪辑。**

镜头一条到底（0 次硬切），观众却能感到换了世界——这是「长镜」和「大胆」
能同时成立的唯一办法。基准实现：`模板/Dazi45.tsx`。

| 段 | 光 | 线条 | 表达 |
|---|---|---|---|
| 1–3 | 暖米白纸感 | 墨线抖动 **ON** | 人的手，松的 |
| 3 末 | **灯灭**（20 帧） | — | 旧物件被扫出画外 |
| 4–6 | 暗场 `#101215` | 抖动 **OFF**，精确刻度 | 机器 |
| 6 末 | **灯亮**（20 帧） | — | 从屏幕里退出来 |
| 7–8 | 暖米白纸感 | 抖动回来 | 回到人的手 |

**六条硬规矩**

1. **灯灭/灯亮都给 20 帧（0.67 秒）。** 给 36 帧，中间会变成一片浑浊的灰褐——
   像雾，不像关灯。
2. **过渡要落在没有字的画面上。** 前段文字先走 → 换光 → 后段文字后到，
   中间空 6～14 帧。文字和换光同时进行，文字会糊在灰里。
3. **段与段交接不能留空拍。** 上一段退场和下一段进场差 10 帧以内。
   黑底上只剩一个小人 = 空屏，验收器的「静止且空」会抓。
4. **暗场分两层画。** 会被压暗的（房间、旧物件）画在暗色遮罩**下面**；
   要亮着的（仪表、数据卡、人）画在遮罩**上面**，用 `mix()` 把颜色切到亮版。
   遮罩透明度 **0.98**，留 2% 保住纸纹——全黑会被判「黑帧」（亮度标准差 < 8）。
5. **三维不用 CSS 3D。** SVG 的 `<g>` 上不可靠。做成「顶面四边形 + 前唇」的实体板，
   和餐桌同一套透视；圆表盘改椭圆 `ry = 0.84 rx`，刻度指针按 `sin/cos` 投影。
   **数字和标签保持直立**——斜文字会毁掉 22px 的可读性。
6. **配色分工要立住。** 陶土红 = 人 / 结论；靛蓝 = 数据 / 仪表 / 被量的那个人。
   一条规则守全片，观众不用听解说也能分出「谁在被量」。

**压白（收尾段）另有一条**：往**更亮的暖白**推（`#fdf8ec`），不能往纸色推（`#f4ecdc`）。
纸色亮度低于「亮部」阈值，压白后整帧均匀，亮部占比会跌到 0.6%，判「静止且空」FAIL。
配一个字距缓慢张开（`0.02 → 0.14em`）给收尾段提供逐帧变化。

**对验收数字的影响**：有暗场的片子，亮部占比会明显升高
（大字理论 17.53%，无暗场的 8.78%），这是正常的，不是异常。
帧差反而可能略低（收尾段压白没有大动作）。

### 阶段 7 · 写组件（改模板，不重写）

打开 `模板/Paper45.tsx`（当前基准），只需要动四处：

1. **顶部调色板 `P`** —— 换主题就是换这几个色值
2. **`CAM` 关键帧表** —— 站位数量、每个站的位置和缓推幅度
3. **`GUIDE` 关键帧表** —— 小人从哪走到哪，什么时候停
4. **各段面板里的文字和数据** —— 逐句替换

时间点全部写成 `B(n)` / `63.83 × n`，不要手写帧号。

#### 7.1 线稿风格必须有的「状态改变」三件套

没有这三样，帧差只有 0.03 级别，等于 PPT：

**① 描线入场**

```tsx
<path pathLength={1} strokeDasharray={1} strokeDashoffset={1 - t} />
```

**② 墨线抖动（最容易漏，漏了就是冻屏）**

```ts
// 两条不同频率的正弦叠加，只抖世界层，不抖屏幕层文字
const boilX = Math.sin(f * 0.44) * 0.55 + Math.sin(f * 1.03 + 2.1) * 0.22;
const boilY = Math.cos(f * 0.51 + 1.1) * 0.5 + Math.cos(f * 0.97 + 0.4) * 0.2;
const camT = `translate(960 540) scale(${cam.k}) translate(${-cam.cx} ${-cam.cy}) translate(${boilX} ${boilY})`;
```

振幅 ±0.72px，单帧位移上限 0.45px。**必须是平滑正弦**，每 3 帧跳一次会闪。

**③ 每镜缓推**

`scale` 从 1 缓慢推到 1.035～1.1，`origin` 在 `50% 46%`。

参考：`~/.workbuddy-ai/skills/innovation-styles/references/风格_08_线条动画.md`、`风格_04_纸艺手绘.md`

#### 7.2 动效词表

| 名字 | 效果 | 参数 |
|---|---|---|
| `em(f, start, dur)` | 淡入 + 0.94→1 + 上浮 16px | 12 帧 |
| `out(f, start, dur)` | 淡出 | 8–12 帧 |
| `drawOn(f, start, dur)` | 描线 | 按线长定 |
| `kf(list, f)` | 关键帧插值 | 配合 `smooth()` |

缓动细节见 `09-动效进阶.md`。

### 阶段 8 · 静帧体检

**每站抽 2～3 帧**（进场 / 稳定态 / 退场），逐张看。不看等于没检查。

```bash
npx remotion still src/index.ts Full45 "草稿/q780.png" --frame=780 --log=error
```

**四张连渲容易在第五张被 SIGTERM**，四张以上放后台跑。

看什么（按出现频率排序）：

| 检查项 | 具体 |
|---|---|
| 文字压字 | 表头 vs 首行、标注 vs 身体、标签 vs 刻度 |
| 元素出画 | 最左/最右的卡片有没有被裁 |
| **文字溢出容器** | 字号加大后列宽/卡高没跟上的，逐条量一遍 |
| 人物穿模 | 走过冰箱/柜子/床，躺下位置在不在床的范围里 |
| **人物站位** | 人的 x 落在家具的 x 区间里没有 |
| 残影 | 上一段的面板是不是还压在新段上 |
| 遮挡 | 卡片有没有切到人物头部 |
| 悬空 | 搁板淡出了，上面的东西还在不在 |

**「文字溢出容器」要按字数量，不能目测。** 中文字宽 ≈ `fontSize`，
22px 的四个字就是 88px，塞进 124px 的列只剩 18px 边距——加上引号就爆了。

```python
宽 = 字数 × fontSize × (1 + letterSpacing)
# 必须 < 列宽 − 2 × 内边距
```

这一轮踩的：`「提升体验」` 带引号 6 个字符 = 110px 塞进 124px 的列，
删除线还横穿过去；`图可大可小` 5 个字 = 110px 直接出了卡片右边缘。

### 阶段 12 · 发布文案

**直接贴在对话里**，三段：标题 / 正文 / 话题。不建文件、不加分析、不给多版本对比。

内容规则：一个事实开场 + 内容 + 金句。不借势平台趋势、不提大促、不写运营话术。
数字出处放评论区，不放在正文里当卖点。

**叙述立场：讲一件事，不讲一个商品。**（2026-10-26 新增）

这是同一条片子两种写法的差别：

| | 讲商品（❌） | 讲一件事（✅） |
|---|---|---|
| 开场 | 一盒塑料豆，几块钱。 | 成年人一年拼了 387 亿次塑料豆。 |
| 中段 | 1971 年瑞典 → 1980s 美国 → 2024 年火了 | 五十年，从康复到玩具，再到解压。**它一直没变，是大人变了。** |
| 结尾 | 所以值得试试。 | 不是大人变小了，是能做完的事变少了。 |
| 读者的感觉 | 在看一个产品介绍 | 在看一件跟自己有关的事 |

**关键差别是那句转折。** 只罗列历史节点，读起来就是产品史；
补一句「它一直没变，是大人变了」，五十年才有指向，才跟读者有关。

标题同理：产品 + 数字（「一盒塑料豆，一年 387 亿次」）像带货，
金句做标题（「不是大人变小了，是能做完的事变少了」）像知识号。
这个号是后者。

**顺带清掉三类词**：价格（几块钱 / 包邮）、种草（好物 / 推荐 / 同款）、商品类目（解压玩具）。
知识片带上这些，读者第一反应是"要卖东西给我"。

> 存档版见 `04-发布文案*.md`（历史归档，格式仅供参考，**不要照着做文件**）。

  数字三层（只画圆环像图钉）。

两处说两套话，用户点进来会觉得被换了片子。

**配色和正片同一套**（`P` 调色板 + 纸纹 + 径向暖光），不要另起一套。
封面是这个号的脸，脸要跟身体是一张。主体是暗场时，暗场色也从正片的 `D` 取。

### ◆ 发布前最后一道 · 违禁词检查（2026-10-26 新增）

验收器 PASS、人眼抽帧过了，片子也不一定能发。**这一道是"能发出去"和"发不出去"的分界。**

```bash
python3 工具/check_words.py src/片子.tsx
python3 工具/check_words.py 文案.md          # 发布文案也扫，评论区同样在审核范围内
```

工具做三件事：从 `.tsx` 里抽出**字符串字面量 + JSX 文本节点**（画面上的每一句字）、
从 `.md` 里抽全文，然后按 10 类词库匹配，输出**行号 + 命中词 + 原文**。

**三级怎么处理**

| 等级 | 含义 | 处理 |
|---|---|---|
| `!!` CRITICAL | 发出去大概率被限流 | **必须改，没有例外** |
| `!` HIGH | 有风险，看语境 | 逐条判断，能换就换 |
| `·` LOW | 提示 | 价格词、运营话术，知识片一般不适用 |

**词库覆盖的 10 类**

站外平台（小红书 / 微博 / 淘宝…）· 导流引流（加微信 / 扫码 / 主页链接）·
医疗健康功效（治疗 / 康复 / 抗认知衰退 / 降血压）· 绝对化用语（最 / 第一 / 唯一 / 100%）·
虚假承诺（永久 / 立竿见影）· 种草带货（好物 / 同款 / 秒杀）· 敏感品类（减肥 / 抗衰）·
金融理财（保本 / 稳赚）· 迷信（风水 / 转运）· 运营话术与价格词

**两条实战教训**

1. **医疗功效表述最隐蔽，因为它读起来是事实陈述。**
   这一轮踩的是「给养老院的老人练手指，**抗认知衰退**」——1971 年那段历史是真的，
   但"抗认知衰退"是功效断言，无资质账号讲就是违规。改法不是删事实，是**只讲行为不讲功效**：
   改成「给养老院的老人用，不是给孩子玩的」，反转还在，功效没了。
   同一条里「康复训练」也命中——换成「手指练习」。

2. **工具会有误报，认一下。** `offset="100%"`、`width="100%"` 这类 SVG 参数会命中「100%」。
   工具已经过滤了「不含中文且不含 3 个以上连续字母」的字符串，剩下偶尔漏的，看一眼行号就知道。

**话题标签单独查**：用 `#家居`，不用 `#家居好物`。「好物 / 推荐 / 种草」会推进电商流量池。

**限流的排查顺序**：违禁词 → 话题带货 → 内容类目 → BGM。
BGM 放最后，因为它最好验证——看别的片子是不是同一首。同一首且别的没事，直接排除。
（详见 `03` 第 29 条）

> **项目文档里的命中不用慌。** `数据.md` / `脚本.md` 是内部台账，
> 里面会记录「小红书 100 亿」「不能碰疗效宣称」这类原文，那是资料不是发布内容。
> 只改 `源文件.tsx` 和**要发出去的那份文案**。

```
│   └── 图片/                   ← 贴图、背景板、Canva 导出图

└── _备份-*/                    ← 整理前的备份，确认无误后可删
```

### 存放规则（2026-10-22 起执行）

1. **桌面根目录不放任何项目文件。** 交付时直接写进 `成片/`，不图省事丢桌面。
2. **一支新片从立项起建 `项目/片名-版本/`**，脚本、分镜表、数据、验收报告全过程放里面，做完归档不删。
3. **成片命名**：`片名_版本_时长.mp4`（例：`深睡自由_纸感长镜版_45秒.mp4`）。
4. **BGM 一律进 `素材/BGM/`**；给 Remotion 用 wav（`bgm-名称.wav`），源文件保留。
5. **交付前跑 `工具/check_video.py`**，验收报告存进 `项目/片名-版本/验收.md`，不达标不交付。
6. **静帧、拼版、测试渲染进 `草稿/`**，命名 `q帧号.png` / `n45_sheet.jpg`，每周清一次。
7. **不确定属于哪类的，先问再动**，不新建文件夹也不乱塞。

### 6.1 画布

| 帧率 | 30 fps |

### 6.2 纸感配色（当前基准）

| 用途 | 变量 | 色值 |
|---|---|---|
| 纸底 | `paper` | `#f4ecdc` |
| 纸底（深） | `paper2` | `#e9dcc3` |
| 主文字 | `ink` | `#2b2622` |
| 次要文字 | `soft` | `rgba(43,38,34,0.72)` |
| 弱文字 / 注释 | `faint` | `rgba(43,38,34,0.48)` |
| 分隔线 | `line` | `rgba(43,38,34,0.22)` |
| 强调 · 陶土红 | `clay` | `#c4532f` |
| 强调 · 芥末黄 | `mustard` | `#e7b23f` |
| 强调 · 鼠尾草绿 | `sage` | `#8fae7c` |
| 强调 · 靛蓝 | `indigo` | `#3b4a6b` |

> 注释用 `faint` 太浅，1080p 缩到手机上会糊。**注释最低用 `soft`**。

### 6.3 字体

| 用途 | 字体栈 |
|---|---|
| 标题（宋体，有书卷气） | `'Source Han Serif SC','Songti SC','STSong','SimSun',serif` |
| 正文（无衬线，清晰） | `'PingFang SC','Microsoft YaHei','Hiragino Sans GB',sans-serif` |
| **阿拉伯数字** | **必须走 sans + `fontWeight={700}`** |

> 宋体的数字笔画细、字距宽，46px 看着比 sans 36px 还弱。中文标题继续用宋体，
> 数字单独走 sans bold，两者混排的层级反而更清楚。（`03` 第 21a 条）

### 6.4 字号（1080p 下，硬指标）

| 层级 | 最小 | 常用 |
|---|---|---|
| 主标题 / 大数字 | 96px | 140–160px |
| 段标题 | 44px | 48–56px |
| **正文** | **26px** | 28–32px |
| **注释** | **20px** | 22–24px |
| 底部字幕 | 34px | **40px** |

**低于 20px 一律不合格。** 改字号必须同步重排版面（`03` 第 20 条）。

字号之外还有三个同等重要的参数：

| 参数 | 要求 | 为什么 |
|---|---|---|
| 文字 alpha | 主色 ≥ 0.84，次级 ≥ 0.64 | 0.48 在纸底上等于浅灰 |
| 数字字体 | sans + bold | 见 6.3 |
| 渲染编码 | `--crf=16 --pixel-format=yuv420p --color-space=bt709` | 默认 `yuvj420p` 2.8 Mbps 会把暗部糊掉 |

> **用户说「文字不清晰」时，先量 WCAG 对比度再动手。**
> 7:1 以上还嫌糊，问题在字号、alpha、字体、码率，不在颜色。（`03` 第 21b 条）

## 七、质量红线（一页纸，出片前逐条打勾）

| 阶段 8 · 静帧体检（3～4 轮） | 60 分钟 | **返工的主要来源** |
| 阶段 10 · 渲染 | 5 分钟（后台） | — |
| ◆ 闸门 C · 验收 + 修（**可能多轮**） | 30～90 分钟 | **可读性返工都在这里** |
| 阶段 11～13 · 归档 + 文案 + 封面 | 25 分钟 | 封面首次 40 分钟，之后 10 分钟 |
| **合计** | **约 6 小时**（第二支起 4 小时） | |

> **最容易犯的错**：跳过阶段 0～2，直接改代码。
> 结果是画面很漂亮，但没人看完——因为开头不抓人，文案没有观点。
> 先花 1 小时想清楚说什么，比花 3 小时调动效值钱得多。
>
> **第二容易犯的错**：跳过闸门 B，直接做 45 秒。
> 深睡自由那一轮，45 秒做完被否两次，等于白干 8 小时。
>
> **第三容易犯的错**：把「改字号」当成一分钟的事。
> 2026-10-23 那一轮，改字号引出了 8 处裁切/溢出、4 处构图冲突，
> 前后渲了 4 遍整片（每遍 5～7 分钟）。**改字号要预留半天，不是半小时。**
>
> **第四容易犯的错**：片子过关了就直接发。
> 2026-10-26 那一轮，验收器 PASS、人眼抽帧四轮都过，
> 但数据卡 21px 注释行里躺着「小红书」——**发出去就被限流**。
> 质量过关和能发出去是两件事，**分发前那一步 grep 不能省，十秒钟的事**。
