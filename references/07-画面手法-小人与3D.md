# 画面手法：小人 · 3D · 版式

> 纯文字的视频，看完记不住是谁做的。
> 一个小人，就能把"信息"变成"有人在跟你讲"。

---

## 一、为什么需要一个角色

知识类视频最难的是**视觉锚点**：满屏文字，观众眼睛没有落点，看着累。

加一个贯穿全片的角色，解决三件事：

1. **视觉中心**：每帧都有一个"人"在那儿，画面立刻有了主体
2. **情绪载体**：他会随拍抬手、会在收尾举手，情绪被具象化了
3. **记忆点**：系列片用同一个角色，观众刷到第二遍就认出来了

**成本**：一个 SVG 组件，200 行，不用建模、不用渲染引擎。

## 二、角色设计

### 2.1 比例：三头身，头大身小

```
viewBox="0 0 260 340"
头：圆心 (130,106)，半径 52   → 头占 104px
身：y 140~250，宽 68
腿：y 246~312
```

头身比接近 **1:2.5**。真人比例在扁平插画里会显得僵硬，三头身才"可爱"。

### 2.2 配色：跟主题走，但只有三个色

| 部位 | 颜色 | 说明 |
|---|---|---|
| 皮肤 | `#F7DFC6` | 暖肤色，比纯白柔和 |
| 头发 | `#33291F` | 深咖，不用纯黑 |
| 衣服 | `#6F8A66`（鼠尾草绿） | 主题色，和背景同一色系 |
| 围裙 | `#FFFCF7` | 提亮，制造层次 |
| 腮红 | `#E07A63` @45% | 一点点就够，多了像贴纸 |

> 衣服颜色**必须**从主题色里取。角色跳色会破坏整片的色彩统一。

### 2.3 脸：三个点就够

```tsx
<circle cx="110" cy="108" r="5.2" fill="#2C2521" />   {/* 左眼 */}
<circle cx="150" cy="108" r="5.2" fill="#2C2521" />   {/* 右眼 */}
<circle cx="112" cy="106" r="1.8" fill="#FFF" />      {/* 高光 */}
<path d="M122 126 Q130 134 138 126" stroke="#2C2521" strokeWidth="3" />
```

眼睛间距 40px（头宽 104 的 38%），嘴角微微上扬 8px。
**不要画鼻子**——扁平风格里鼻子是噪音。

### 2.4 代码骨架

```tsx
const LittleMan: React.FC<{ x: number; y: number; scale: number; lift?: number }> = ({
  x, y, scale, lift = 0,
}) => {
  const frame = useCurrentFrame();

  // 每拍一次的脉冲
  const beatPos = (frame / FPS - BEAT_OFFSET) / BEAT_SEC;
  const frac = beatPos - Math.floor(beatPos);
  const pulse = Math.pow(1 - frac, 3);

  const breathe = Math.sin(frame * 0.055) * 3;   // 呼吸：慢速正弦
  const armLift = 30 * pulse + lift * 55;        // 抬手：踩拍 + 场景加成
  const squash = 1 + 0.05 * pulse;               // 挤压：踩拍变形
  const sway = Math.sin(frame * 0.045) * 2.4;    // 摇头：更慢的正弦

  return (
    <div style={{
      position: "absolute", left: x, top: y,
      transform: `translate(-50%, -100%) scale(${scale})`,
      transformOrigin: "50% 100%",              // 以脚为原点缩放
      filter: `drop-shadow(0 26px 26px rgba(74,52,38,0.28))`,
    }}>
      <svg width="260" height="340" viewBox="0 0 260 340"
        style={{
          transform: `translateY(${breathe - 4 * pulse}px)
                      scaleY(${squash}) scaleX(${2 - squash})`,
          transformOrigin: "50% 100%",
        }}>
        {/* 影子、腿、手臂、身体、头 */}
      </svg>
    </div>
  );
};
```

**三个关键点**：

1. `transformOrigin: "50% 100%"` —— 以脚为支点，呼吸和挤压才不会"飘起来"
2. `scaleY(squash) scaleX(2 - squash)` —— 压扁的同时横向拉宽，体积守恒
3. 手臂用 `<g transform="rotate(角度 支点)">` 包一层，改角度就行

## 三、角色动效：三种，不要更多

| 动效 | 频率 | 幅度 | 作用 |
|---|---|---|---|
| 呼吸 | `sin(frame * 0.055)` ≈ 5.5 秒一个来回 | ±3px | 让角色"活着" |
| 踩拍抬手 | 每拍一次，指数衰减 | 30° | 和音乐同步 |
| 场景移动 | 场景切换时 12 帧过渡 | 全屏 | 引导视线 |

### 位置怎么走

角色不是钉在一个地方，而是**跟着内容走**：

```
钩子       → 居中 (960, 1055)   scale 1.12
五类总览   → 居中 (960, 1055)   scale 1.12
细讲 ①~⑤  → 左侧 (320, 1055)   scale 0.90
避坑 / 清单 → 右侧 (1700, 1055) scale 0.84
收尾       → 居中 (960, 1055)   scale 1.12
```

```tsx
const manX = interpolate(
  frame,
  [S1, S3 - 12, S3, S6 - 12, S6, S8 - 12, S8],
  [960, 960, 320, 320, 1700, 1700, 960],
  { extrapolateLeft: "clamp", extrapolateRight: "clamp" }
);
```

**规律**：内容在右，人就站左；内容在左，人就站右。中间有大标题时，人回到中间。

## 四、3D 效果：CSS perspective 就够了

不用 Three.js。Remotion 跑在 Chrome 里，`perspective` + `rotateY/rotateX` 就能做出有说服力的立体感。

### 4.1 扇形卡片墙

五张卡排成一排，各自朝中心转一点角度，中间高两边低：

```tsx
const offset = index - 2;   // -2, -1, 0, 1, 2

style={{
  transform: `
    translateX(${offset * 268}px)
    translateY(${(1 - p) * 120 + Math.abs(offset) * 26}px)
    perspective(1400px)
    rotateY(${offset * -11}deg)
    rotateX(${4 + Math.abs(offset) * 1.5}deg)
    scale(${0.94 + p * 0.06})`,
  opacity: p,
}}
```

- `rotateY(offset * -11deg)` —— 左右各转 11°，形成弧形墙
- `translateY(abs(offset) * 26)` —— 中间高、两边低，像摊开的扇子
- `perspective(1400px)` 值越小透视越夸张，1400 是"轻 3D"

**入场**：`(1-p)*120` 从下方升起 + `scale` 从 0.94 到 1，配合 spring。

### 4.2 等距地台

角色脚下放一个旋转的等距网格，瞬间有"站在空间里"的感觉：

```tsx
<div style={{
  transform: `translate(-50%,-50%) scale(${scale})
              perspective(1100px) rotateX(64deg) rotateZ(${spin}deg)`,
}}>
  {/* 外圈光晕 */}
  <div style={{ borderRadius: "50%",
    background: `radial-gradient(circle, ${accent}22 0%, transparent 62%)` }} />
  {/* 网格 */}
  <div style={{
    borderRadius: "50%",
    backgroundImage: `
      linear-gradient(${ink}0F 1px, transparent 1px),
      linear-gradient(90deg, ${ink}0F 1px, transparent 1px)`,
    backgroundSize: "44px 44px",
  }} />
</div>
```

- `rotateX(64deg)` 是把平面"压扁"成地面的关键，60~70° 之间
- `rotateZ(spin)` 让它缓慢旋转（`spin = frame * 0.12`）
- 网格透明度 `0F`（6%）—— 再高就抢戏了

### 4.3 深度排序

**角色永远最后渲染**（放在 JSX 最后），这样他总是在最上层，形成"人在前、卡片在后"的纵深。

如果要让角色被卡片挡住（更真实），就把他渲染在卡片前面。二选一，不要混。

## 五、版式与安全区（最容易翻车的地方）

### 5.1 画布分区

```
1920 × 1080
┌─────────────────────────────┐
│ 96                          │  ← 顶部标识（y=50）
│    ┌───────────────────┐    │
│    │  内容区           │    │  ← y: 110 ~ 800
│    │  左 160 / 右 1760 │    │
│    └───────────────────┘    │
│         ▲  小人            │  ← 脚在 y=1055，头顶约 y=675
└─────────────────────────────┘
```

### 5.2 三条硬规则

**① 角色头顶上方不能有文字**

角色 scale=1.12 时高 340×1.12 ≈ 381px，脚在 1055 → 头顶在 **674**。
所以任何内容块的底边**必须 ≤ 660**。

**② 居中式场景要给底部留白**

```tsx
<AbsoluteFill style={{ paddingBottom: 320 }}>  {/* 把内容整体上移 160px */}
```

不留白，居中布局的副文案就会正好压在小人头上（实测第一版就是这样翻车的）。

**③ 侧边角色要留出横向空间**

角色在左侧时占 x ∈ [190, 450]（scale 0.9，宽 260×0.9=234）。
所以右侧内容块从 **x=700** 开始，左边永远不重叠。

### 5.3 自查方法

渲染 3 个帧就能看出问题：**每个场景的"内容最满"那一帧**。

```bash
npx remotion still src/index.ts Double11 out/check.png --frame=630
```

看四件事：
- [ ] 小人的头有没有压到字
- [ ] 最右边的卡片有没有出画
- [ ] 内容块底部有没有超过 y=660
- [ ] 两张卡片之间有没有粘连（间距 < 24px 就会糊在一起）

### 5.4 竖屏（9:16）要重排版式，不是裁一刀

抖音竖屏占比已经过半，但**16:9 直接裁成 9:16 会切掉两侧内容**，必须重排。

**规格**（2026 年平台要求）：

| 项 | 值 |
|---|---|
| 分辨率 | 1080 × 1920 |
| 编码 | H.264 / AAC |
| 帧率 | 30fps |
| 码率 | ≥ 4000 kbps（比横屏高一倍） |

**安全区**（这是竖屏最关键的一点）：

```
1080 × 1920
┌──────────────────┐  ← y=0
│   顶部 10% 留白   │     平台标题、返回键
│                  │
│   ┌──────────┐   │
│   │          │   │
│   │  内容区  │   │  ← 实际可用约 y: 190 ~ 1500
│   │          │   │
│   └──────────┘   │
│                  │
│   底部 18% 留白   │     文案、音乐名、评论框
└──────────────────┘  ← y=1920
                ↑
          右侧 120px 避让（点赞/评论/分享按钮）
```

换算成数字（1080×1920）：

- **顶部**：y < 190 不放内容
- **底部**：y > 1500 不放内容（18% = 346px，是平台按钮和文案区）
- **右侧**：x > 960 开始收窄，**关键内容不超过 x=920**（给右侧按钮栏让位）
- **可用内容区**：约 `1000 × 1310`

**版式怎么改**：

| 横屏做法 | 竖屏改成 |
|---|---|
| 左文右图 | 上下叠：文在上，图在下 |
| 5 张卡片横排 | 2 行（3+2）或纵向堆叠 |
| 表格 5 行 | 保留，但行高压缩、字号降一档 |
| 小人站左下角 | 小人站**底部中间偏下**，或站在内容旁边的小尺寸 |

**竖屏的优势**：单屏信息量少，但**节奏可以更快**——同样的内容，竖屏停留时间可以缩短 20%。

> 竖屏适配的工作量约等于重做一遍版式，不是改个尺寸就行。
> 所以第 ① 步澄清时必须问清"横屏还是竖屏"，不能等做完再改。

## 六、什么时候不该加小人

| 场景 | 建议 |
|---|---|
| 纯数据图表、走势图 | 不加，图表本身就是视觉主体 |
| 严肃话题（财经、医疗、政策） | 不加，可爱角色会削弱可信度 |
| 高密度信息页（表格 > 6 行） | 不加，会挤占空间 |
| 系列片的"正片" | 加，作为账号识别符号 |

> 判断标准：这个角色是"帮观众理解"，还是"帮画面填空"？
> 前者加，后者不加。
